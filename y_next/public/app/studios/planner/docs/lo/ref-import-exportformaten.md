# ຮູບແບບການນຳເຂົ້າ ແລະ ສົ່ງອອກ

ສຳລັບແຕ່ລະຮູບແບບໄຟລ໌: ທ່ານເປີດໄດ້ບໍ່, ບັນທຶກໄດ້ບໍ່ ແລະ ສົ່ງອອກໄດ້ບໍ່, ຂໍ້ມູນໃດຕິດໄປນຳ ແລະ ໃດບໍ່ຕິດໄປ, ແລະ ເປີດດ້ວຍໂປຣໄຟລ໌ການຄິດໄລ່ໃດ. ເຫດຜົນເບື້ອງຫຼັງທັງໝົດນີ້ ແລະ ຕົວຢ່າງທີ່ມີຕົວເລກ ຢູ່ໃນ [ໄຟລ໌ ແລະ ຮູບແບບ](docs://uitleg-bestanden).

## ພາບລວມ

**ການເປີດ** ໃຊ້ໄດ້ກັບ IFC, CSV, MS Project XML, Primavera P6 XML, `.mpp` ແລະ `.xer`. ໄຟລ໌ທີ່ມີນາມສະກຸນອື່ນ ແອັບຈະຖືວ່າເປັນ IFC.

**ການບັນທຶກ** ຂຽນເປັນ IFC ສະເໝີ. ມີແຕ່ໄຟລ໌ IFC ທີ່ເປີດແລ້ວເທົ່ານັ້ນ ທີ່ກາຍເປັນເປົ້າໝາຍການບັນທຶກ; ໂຄງການຈາກຮູບແບບອື່ນ ບໍ່ມີໄຟລ໌ຫຼັງຈາກເປີດ ແລະ *ບັນທຶກ* ຈະຖາມວ່າໄຟລ໌ IFC ຄວນຖືກບັນທຶກໄວ້ບ່ອນໃດ.

**ການສົ່ງອອກ** ໃຊ້ໄດ້ກັບ IFC 4x3, MS Project XML, Primavera P6 XML, CSV ແລະ ໃບຄວາມຄືບໜ້າ ສອງແບບ (Excel ແລະ CSV). ການສົ່ງອອກ ບໍ່ປ່ຽນໂຄງການຂອງທ່ານ.

**ອ່ານຢ່າງດຽວ** ແມ່ນ `.mpp` ແລະ `.xer`: ແອັບເປີດໄຟລ໌ເຫຼົ່ານີ້ໄດ້ ແຕ່ຂຽນບໍ່ໄດ້.

**PDF** ມາຈາກລາຍງານເທົ່ານັ້ນ (ເບິ່ງ [ປະເພດບົດລາຍງານ](docs://ref-rapporttypes)). ແອັບບໍ່ອ່ານ PDF.

**ບ່ອນ.** ການເປີດ: *ໜ້າຫຼັກ › ໄຟລ໌ › ເປີດ*, *ໄຟລ໌ › ເປີດ* ຫຼື Ctrl+O. ການສົ່ງອອກ: *ໜ້າຫຼັກ › ໄຟລ໌ › ສົ່ງອອກ* ຫຼື *ໄຟລ໌ › ສົ່ງອອກ*. ທ່ານອ່ານໃບຄວາມຄືບໜ້າທີ່ຕື່ມຂໍ້ມູນແລ້ວ ໂດຍ *ໄຟລ໌ › ນຳເຂົ້າ* ຫຼືດ້ວຍປຸ່ມ *ອັບເດດຄວາມຄືບໜ້າຈາກສະເປຣດຊີດ* ໃນກຸ່ມ *ຄວາມຄືບໜ້າ* ຂອງແຖບເຄື່ອງມື ໃນແຖບ *ການວາງແຜນ*, *ຕາຕະລາງ* ແລະ *ລາຍງານ*.

**ໂປຣໄຟລ໌ການຄິດໄລ່ເມື່ອເປີດ.** ທຸກຮູບແບບເປີດດ້ວຍໂປຣໄຟລ໌ການຄິດໄລ່. ໂປຣໄຟລ໌ນັ້ນແມ່ນຫຍັງ ຢູ່ໃນ [ຕົວເລືອກການຄິດໄລ່ ແລະ ຂໍ້ກຳນົດ](docs://ref-rekenopties-en-conventies). `.xer` ເປີດດ້ວຍ *Primavera P6*, `.mpp` ດ້ວຍ *Microsoft Project*, ແລະ CSV, MS Project XML ແລະ P6 XML ດ້ວຍ *Open Planner Studio*. IFC ຮັກສາໂປຣໄຟລ໌ທີ່ບັນທຶກໄວ້ໃນໄຟລ໌. ສຳລັບ `.xer` ແລະ `.mpp` ແອັບລາຍງານວ່າໂຄງການຄິດໄລ່ດ້ວຍວິທີນີ້. ມີແຕ່ IFC ທີ່ບັນທຶກໂປຣໄຟລ໌ການຄິດໄລ່ ແລະ ຕົວເລືອກການຄິດໄລ່; ໃນຕົວເລືອກການຄິດໄລ່ MS Project XML ຂຽນພຽງແຕ່ເກນກຳນົດວິກິດເທົ່ານັ້ນ. ໄຟລ໌ສົ່ງອອກຈາກຮູບແບບອື່ນ ເມື່ອເປີດຄືນ ຈະຄິດໄລ່ເປັນ *Open Planner Studio*.

## IFC

**ເປີດ** — ໄດ້, `.ifc`. ແອັບອ່ານ IFC 4.3. ໂປຣໄຟລ໌ການຄິດໄລ່: ອັນທີ່ຢູ່ໃນໄຟລ໌.

**ບັນທຶກ** — ໄດ້, ແລະ ນີ້ແມ່ນຮູບແບບດຽວທີ່ບັນທຶກໄດ້. *ບັນທຶກ* ຂຽນທັງໂຄງການຂອງທ່ານເປັນໄຟລ໌ IFC. ໄຟລ໌ນັ້ນກາຍເປັນເປົ້າໝາຍການບັນທຶກ.

**ສົ່ງອອກ** — ໄດ້, ເປັນ *IFC 4x3* (ອະທິບາຍວ່າ *ມາດຕະຖານ BuildingSMART. ເຊື່ອມຕໍ່ແບບ 4D ກັບໂມເດວ BIM.*). ຊື່ເລີ່ມຕົ້ນ: ຊື່ໂຄງການ ພ້ອມນາມສະກຸນ `.ifc`. ຖ້າໂຄງການຂອງທ່ານເຊື່ອມກັບຄັງຂໍ້ມູນ, ຊ່ອງໝາຍ *ບັນທຶກໄຟລ໌ຄັງຂໍ້ມູນໄວ້ຄຽງຄູ່ກັນ* ຢູ່ລຸ່ມກາດ ໃນ *ໄຟລ໌ › ສົ່ງອອກ*. ເມື່ອໝາຍຖືກ ແອັບຈະຖາມຫາບ່ອນເກັບ *ຊື່ໂຄງການ-ຄັງຂໍ້ມູນ.ifc* ຫຼັງຈາກໂຄງການ. ຊ່ອງໝາຍນີ້ບໍ່ຢູ່ໃນລາຍການໃນແຖບ *ໜ້າຫຼັກ*.

**ສິ່ງທີ່ຕິດໄປນຳ** — ທຸກຢ່າງທີ່ເປັນຂອງໂຄງການ: ໜ້າວຽກພ້ອມໂຄງສ້າງ, ໄລຍະເວລາ, ວັນທີ ແລະ ຄວາມຄືບໜ້າ; ສາຍສຳພັນພ້ອມຄ່າ Lag; ເງື່ອນໄຂ ແລະ ກຳນົດສົ່ງ; ປະຕິທິນ; ຊັບພະຍາກອນ ແລະ ການມອບໝາຍ ລວມທັງການກະຈາຍຕາມຊົ່ວໂມງ; ແຜນຫຼັກ; ລະຫັດກິດຈະກຳ ແລະ ຊ່ອງກຳນົດເອງ; ໝາຍເຫດ; ສາຍສຳພັນພາຍນອກກັບໂຄງການອື່ນ; ຊ່ວງພັກ; ກົດເກນວຽກ ແລະ ປະເພດໜ້າວຽກ; ການຕັ້ງຄ່າໂຄງການ ເຊັ່ນ ວັນທີສະຖານະ, ຮູບແບບຄວາມຄືບໜ້າ, ໂປຣໄຟລ໌ການຄິດໄລ່ ແລະ ຕົວເລືອກການຄິດໄລ່; ການເຊື່ອມກັບຄັງຂໍ້ມູນ. ສຳລັບໂຄງການຈາກ `.xer`, ໄຟລ໌ຕົ້ນສະບັບກໍຕິດໄປນຳເຊັ່ນກັນ. ປະເພດໜ້າວຽກກຳນົດເອງ ຖືກເກັບເປັນປະເພດ IFC `USERDEFINED` ໂດຍມີຊື່ຂອງມັນຢູ່ໃນຊ່ອງ ObjectType, ດັ່ງນັ້ນໂປຣແກຣມ IFC ອື່ນອ່ານໜ້າວຽກໄດ້ປົກກະຕິ; ແອັບຍັງເກັບ id ຄົງທີ່ຂອງປະເພດ, ດັ່ງນັ້ນການປ່ຽນຊື່ບໍ່ທຳລາຍການເຊື່ອມ. ຖ້າຜູ້ໜຶ່ງເປີດໄຟລ໌ໃນຄອມພິວເຕີອື່ນ ປະເພດນັ້ນຈະປາກົດຢູ່ທີ່ນັ້ນພາຍໃຕ້ *ຈາກໂຄງການນີ້*, ບໍ່ແມ່ນໃນ *ປະເພດໜ້າວຽກຂອງຂ້ອຍ* ຂອງເພິ່ນ.

**ສິ່ງທີ່ບໍ່ຕິດໄປນຳ** — ການຕັ້ງຄ່າໜ້າຈໍຂອງທ່ານ (ການຊູມ, ຕຳແໜ່ງເລື່ອນ, ໜ້າວຽກທີ່ເລືອກ, ກຸ່ມທີ່ພັບໄວ້, ຕົວກອງ ແລະ ການຈັດກຸ່ມທີ່ເລືອກ) ແລະ ການຕັ້ງຄ່າແອັບ ([ການຕັ້ງຄ່າ](docs://ref-instellingen)). ແຖບ *IFC* ສະແດງຂໍ້ຄວາມ IFC ຂອງໂຄງການທ່ານ.

## MS Project XML (MSPDI)

**ເປີດ** — ໄດ້. ແອັບຈຳໄຟລ໌ `.xml` ວ່າເປັນ MS Project XML ຈາກອົງປະກອບຮາກ `Project` ໃນຊ່ອງຊື່ (namespace) ຂອງ MS Project (ຫຼືບໍ່ມີຊ່ອງຊື່). ໂປຣໄຟລ໌ການຄິດໄລ່: *Open Planner Studio*.

**ບັນທຶກ** — ບໍ່ໄດ້. ໂຄງການແບບນີ້ບໍ່ມີເປົ້າໝາຍການບັນທຶກ.

**ສົ່ງອອກ** — ໄດ້, ເປັນ *MS Project XML* (*ເປີດໃນ Microsoft Project ໄດ້. ຮັກສາໂຄງສ້າງ WBS ຄົບຖ້ວນ.*). ຊື່ເລີ່ມຕົ້ນ: ຊື່ໂຄງການ ພ້ອມ `.xml`.

**ສິ່ງທີ່ຕິດໄປນຳ** — ໜ້າວຽກພ້ອມໂຄງສ້າງ (ລະດັບ ແລະ WBS), ໄລຍະເວລາ, ວັນທີ ແລະ ຄວາມຄືບໜ້າ; ສາຍສຳພັນພ້ອມຄ່າ Lag, ທັງເປັນຊົ່ວໂມງ ຫຼື ເປັນເປີເຊັນ; ເງື່ອນໄຂ ລວມທັງກຳນົດສົ່ງ; ປະຕິທິນ ລວມທັງປະຕິທິນຂອງໜ້າວຽກ ແລະ ຂອງຊັບພະຍາກອນ; ຊັບພະຍາກອນ ແລະ ການມອບໝາຍ ລວມທັງເສັ້ນໂຄ້ງ ຫຼື ການກະຈາຍຕາມຊົ່ວໂມງ; ວັນທີສະຖານະ; ເກນກຳນົດວິກິດ ເປັນຈຳນວນເຕັມຂອງມື້ເຮັດວຽກ 0 ຂຶ້ນໄປ ພ້ອມ *ໄລຍະຜ່ອນຜັນລວມ ≤ ເກນກຳນົດ*; ລາຍລະອຽດຂອງໜ້າວຽກ (ເປັນໝາຍເຫດ); ກົດເກນວຽກຂອງໜ້າວຽກ (ເປັນປະເພດໜ້າວຽກຂອງ Microsoft Project); ປະເພດໜ້າວຽກກຳນົດເອງ ໃນຊ່ອງອິດສະຫຼະ (`ExtendedAttribute`) ທີ່ແອັບອ່ານກັບຄືນ ແລະ ທີ່ Microsoft Project ອາດບໍ່ສົນໃຈ. ໃນແຜນຫຼັກຂອງທ່ານ ມີແຕ່ອັນທີ່ໃຊ້ຢູ່ເທົ່ານັ້ນ ທີ່ຕິດໄປນຳ, ເປັນແຜນຫຼັກ 0. ໜ້າວຽກທີ່ເປັນຊົ່ວໂມງ ຮັກສາຫົວໜ່ວຍຂອງມັນ, ແລະ ຫຼັກໝາຍ ຮັກສາປະເພດຂອງມັນ (ເລີ່ມ, ສິ້ນສຸດ ຫຼື ອັດຕະໂນມັດ).

**ສິ່ງທີ່ບໍ່ຕິດໄປນຳ** — ໝາຍເຫດ (ລາຍການກວດສອບຂອງໜ້າວຽກ), ສາຍສຳພັນພາຍນອກກັບໂຄງການອື່ນ, ລະຫັດກິດຈະກຳ ແລະ ຊ່ອງກຳນົດເອງ, ເງື່ອນໄຂທີສອງ, ເຄື່ອງໝາຍ *ກຳນົດເວລາດ້ວຍຕົນເອງ*, ຄວາມຊັກຊ້າຈາກການປັບສົມດຸນ, ຈຸດດຳເນີນຕໍ່ ແລະ ຈຸດຢຸດຂອງໜ້າວຽກທີ່ມີຄວາມຄືບໜ້າຂ້າມລຳດັບ, ຂໍ້ກຳນົດ *ວຽກທີ່ເຫຼືອເລີ່ມຕໍ່ຫຼັງຈາກໄລຍະເວລາທີ່ຜ່ານໄປ* ແລະ *ບໍ່ຍ້າຍໜ້າວຽກທີ່ຍັງບໍ່ເລີ່ມໄປທີ່ວັນທີສະຖານະ* ຂອງໂປຣໄຟລ໌ Microsoft Project, ແລະ ຕົວເລືອກການຄິດໄລ່ອື່ນໆ. ໜ້າວຽກທີ່ມີຊ່ວງພັກ ທີ່ບໍ່ມີການກະຈາຍຕາມຊົ່ວໂມງ ຕິດໄປນຳໂດຍບໍ່ມີຊ່ວງພັກຂອງມັນ.

**ສິ່ງທີ່ປ່ຽນລະຫວ່າງທາງ** — ເງື່ອນໄຂ *ຕ້ອງເລີ່ມໃນວັນທີ (MSO)* ຫຼື *ຕ້ອງສິ້ນສຸດໃນວັນທີ (MFO)* ໂດຍບໍ່ມີທາງເລືອກ *ບັງຄັບ (ປັກໝຸດແໜ້ນ)* ຈະກາຍເປັນ *ເລີ່ມບໍ່ກ່ອນ (SNET)* ຫຼື *ສິ້ນສຸດບໍ່ກ່ອນ (FNET)*. ແຮມມັອກກາຍເປັນໜ້າວຽກທຳມະດາ ທີ່ມີວັນທີທີ່ຄິດໄລ່ແລ້ວ.

## ໄຟລ໌ Microsoft Project (`.mpp`)

**ເປີດ** — ໄດ້, ຈາກ Microsoft Project 2010 ຫາ 2021. ໂປຣໄຟລ໌ການຄິດໄລ່: *Microsoft Project*. ແອັບອ່ານໄຟລ໌ເທົ່ານັ້ນ: ມັນບໍ່ປ່ຽນ `.mpp` ຂອງທ່ານເລີຍ. ໄຟລ໌ຈາກ Microsoft Project 2007 ຫຼື ເກົ່າກວ່າ, ແລະ ໄຟລ໌ທີ່ມີລະຫັດຜ່ານ, ແອັບຈະປະຕິເສດ ດ້ວຍຂໍ້ຄວາມທີ່ຊີ້ໄປຫາການສົ່ງອອກ XML ຂອງ Microsoft Project.

**ບັນທຶກ** — ບໍ່ໄດ້, ແລະ ບໍ່ມີເປົ້າໝາຍການບັນທຶກ: *ບັນທຶກ* ຂຽນໄຟລ໌ IFC ໃໝ່.

**ສົ່ງອອກ** — ບໍ່ໄດ້.

**ສິ່ງທີ່ຕິດໄປນຳ** — ໜ້າວຽກພ້ອມໂຄງສ້າງ, ໄລຍະເວລາ ແລະ ເງື່ອນໄຂ; ສາຍສຳພັນພ້ອມຄ່າ Lag; ປະຕິທິນ; ຊັບພະຍາກອນ ແລະ ການມອບໝາຍ; ຄວາມຄືບໜ້າ; ລະຫັດ WBS ທີ່ທ່ານໃສ່ເອງໃນ Microsoft Project. ວັນທີ ແລະ float ທີ່ Microsoft Project ຄິດໄລ່ເອງ ກໍຖືກອ່ານເຊັ່ນກັນ ສຳລັບມຸມມອງ *ວັນທີຕາມທີ່ບັນທຶກ*.

**ສິ່ງທີ່ບໍ່ຕິດໄປນຳ** — ແຜນຫຼັກ, ຕົ້ນທຶນ ແລະ ອັດຕາຄ່າໃຊ້ຈ່າຍ, ໝາຍເຫດ ແລະ ຊ່ອງກຳນົດເອງຂອງ Microsoft Project. ເບິ່ງ [ການເປີດໄຟລ໌ Microsoft Project (.mpp)](docs://howto-mpp-openen).

**ທີ່ມາ ແລະ ໃບອະນຸຍາດ** — ໂຕອ່ານ `.mpp` ຖືກຂຽນສຳລັບ Open Planner Studio ແລະ ໄດ້ມາຈາກໂຄ້ດຕົ້ນສະບັບ ແລະ ຄວາມຮູ້ດ້ານໂຄງສ້າງຂອງ MPXJ (`github.com/joniles/mpxj`, Jon Iles ແລະ ຄະນະ), ເປັນຫໍສະໝຸດ Java ພາຍໃຕ້ LGPL-2.1. ໂຄງສ້າງ ແລະ ຄ່າຄົງທີ່ຂອງຊ່ອງຖືກປ່ຽນເປັນ TypeScript. Open Planner Studio ເອງເປັນຊອບແວເປີດພາຍໃຕ້ LGPL-3.0. ໂຕອ່ານ `.xer` ບໍ່ແມ່ນອະນຸພັນ: MPXJ ຖືກປຶກສາໃນສ່ວນນັ້ນ ພຽງແຕ່ເປັນແຫຼ່ງຄວາມເຂົ້າໃຈ.

## Primavera P6 XML

**ເປີດ** — ໄດ້. ແອັບຈຳໄຟລ໌ `.xml` ວ່າເປັນ P6 XML ຈາກອົງປະກອບຮາກ `APIBusinessObjects`. ໂປຣໄຟລ໌ການຄິດໄລ່: *Open Planner Studio*.

**ບັນທຶກ** — ບໍ່ໄດ້.

**ສົ່ງອອກ** — ໄດ້, ເປັນ *Primavera P6 XML* (*ສຳລັບ Oracle Primavera P6.*). ຊື່ເລີ່ມຕົ້ນ: ຊື່ໂຄງການ ພ້ອມ `.xml`, ດັ່ງນັ້ນຈຶ່ງເປັນຊື່ດຽວກັນກັບການສົ່ງອອກ MS Project XML: ທ່ານຕ້ອງຕັ້ງຊື່ໃຫ້ແຕກຕ່າງກັນດ້ວຍຕົນເອງ.

**ສິ່ງທີ່ຕິດໄປນຳ** — ໂຄງສ້າງ WBS ແລະ ໜ້າວຽກທີ່ມີໄລຍະເວລາ, ວັນທີ ແລະ ຄວາມຄືບໜ້າ; ສາຍສຳພັນພ້ອມຄ່າ Lag; ເງື່ອນໄຂ (ລວມເງື່ອນໄຂທີສອງ ເປັນເງື່ອນໄຂອ່ອນ); ປະຕິທິນ; ຊັບພະຍາກອນ ແລະ ການມອບໝາຍ; ວັນທີສະຖານະ (ເປັນ `DataDate`); ປະເພດໜ້າວຽກກຳນົດເອງ ໃນຊ່ອງຂອງມັນເອງ `OPS Custom Task Type` ທີ່ແອັບອ່ານກັບຄືນ ແລະ ທີ່ P6 ອາດບໍ່ສົນໃຈ.

**ສິ່ງທີ່ບໍ່ຕິດໄປນຳ** — ແຜນຫຼັກ ແລະ ກຳນົດສົ່ງ; ລະຫັດກິດຈະກຳ, ຊ່ອງກຳນົດເອງ, ໝາຍເຫດ ແລະ ສາຍສຳພັນພາຍນອກ; ຕົວເລືອກການຄິດໄລ່. P6 ບໍ່ມີຄ່າ Lag ເປັນເປີເຊັນ: ແອັບປ່ຽນມັນເປັນຈຳນວນມື້ຄົງທີ່. ຄ່າ Lag ເປັນມື້ຕາມປະຕິທິນ ກາຍເປັນຄ່າ Lag ເປັນເວລາເຮັດວຽກ: 3 ມື້ຕາມປະຕິທິນ ກາຍເປັນ 3 ມື້ເຮັດວຽກ. ແຮມມັອກກາຍເປັນໜ້າວຽກທຳມະດາ, ໜ້າວຽກທີ່ກຳນົດເວລາດ້ວຍຕົນເອງ ກາຍເປັນໜ້າວຽກທຳມະດາທີ່ມີວັນທີທີ່ຄິດໄລ່ແລ້ວ, ແລະ ຄວາມຊັກຊ້າຈາກການປັບສົມດຸນທີ່ໜ້ອຍກວ່າໜຶ່ງມື້ ຖືກຕັດອອກ.

## ໄຟລ໌ Primavera (`.xer`)

**ເປີດ** — ໄດ້. ໂປຣໄຟລ໌ການຄິດໄລ່: *Primavera P6*. ແອັບອ່ານໄຟລ໌ເທົ່ານັ້ນ: ມັນບໍ່ຂຽນ `.xer` ແລະ ບໍ່ປ່ຽນໄຟລ໌ຂອງທ່ານເລີຍ. ມັນເປີດໜຶ່ງແຖບຕໍ່ໂຄງການທີ່ມີໜ້າວຽກ. ໄຟລ໌ທີ່ບໍ່ມີໜ້າວຽກ ຫຼື ມີຕາຕະລາງເສຍຫາຍ ແອັບຈະປະຕິເສດດ້ວຍຂໍ້ຄວາມ.

**ບັນທຶກ** — ບໍ່ໄດ້, ແລະ ບໍ່ມີເປົ້າໝາຍການບັນທຶກ: *ບັນທຶກ* ຂຽນໄຟລ໌ IFC ໃໝ່, ໂດຍມີ `.xer` ຕົ້ນສະບັບຢູ່ຂ້າງໃນ.

**ສົ່ງອອກ** — ບໍ່ໄດ້. ຖ້າທ່ານສົ່ງອອກໂຄງການຈາກ `.xer` ເປັນ CSV, MS Project XML ຫຼື P6 XML, ແອັບລາຍງານວ່າຂໍ້ມູນຕົ້ນສະບັບ XER ສູນຫາຍ, ເຖິງແມ່ນທ່ານຈະບັນທຶກໂຄງການເປັນ IFC ໃນລະຫວ່າງນັ້ນແລ້ວກໍຕາມ. ເປັນ IFC ບໍ່ມີຫຍັງສູນຫາຍ.

**ສິ່ງທີ່ຕິດໄປນຳ** — ໂຄງສ້າງ WBS ແລະ ໜ້າວຽກທີ່ມີໄລຍະເວລາ, ວັນທີ, ເງື່ອນໄຂ ແລະ ຄວາມຄືບໜ້າ; ສາຍສຳພັນພ້ອມຄ່າ Lag; ປະຕິທິນ; ຊັບພະຍາກອນພ້ອມການມອບໝາຍ; ລະຫັດກິດຈະກຳ; ຊ່ອງກຳນົດເອງ (UDF); ໝາຍເຫດ; ການຕັ້ງຄ່າແຜນງານຂອງ P6. ໜ້າວຽກປະເພດ *ລະດັບຄວາມພະຍາຍາມ* ກາຍເປັນແຮມມັອກ. ໂຄງການແຜນຫຼັກ ກາຍເປັນແຜນຫຼັກທີ່ໃຊ້ຢູ່ຂອງໂຄງການທີ່ອ້າງເຖິງມັນ. ສາຍສຳພັນລະຫວ່າງສອງໂຄງການ ແອັບເກັບໄວ້ເປັນຂໍ້ມູນຕົ້ນສະບັບ.

**ສິ່ງທີ່ບໍ່ຕິດໄປນຳ** — ໂຄງການທີ່ບໍ່ມີໜ້າວຽກ, ແລະ ສາຍສຳພັນລະຫວ່າງສອງໂຄງການ ເປັນສາຍສຳພັນຈິງໃນແຜນງານຂອງທ່ານ. ເບິ່ງ [ການເປີດໄຟລ໌ Primavera P6 (.xer)](docs://howto-xer-openen).

## CSV

**ເປີດ** — ໄດ້. ແອັບອ່ານ `;` ແລະ `,` ເປັນຕົວແຍກ. ມັນຈຳຫົວຖັນເປັນພາສາອັງກິດ ແລະ ພາສາດັດ (ຕົວຢ່າງ `Name` ຫຼື `Naam`, `Duration` ຫຼື `Duur`, `Predecessors` ຫຼື `Voorgangers`). ວັນທີອາດເປັນ *ປປປປ-ດດ-ວວ*, *ວວ-ດດ-ປປປປ* ຫຼື *ວວ/ດດ/ປປປປ*. ທ່ານຂຽນໜ້າວຽກກ່ອນໜ້າເປັນລະຫັດ WBS, ປະເພດສາຍສຳພັນ ແລະ ຄ່າ Lag, ຕົວຢ່າງ `1.2FS+2d`. ໂປຣໄຟລ໌ການຄິດໄລ່: *Open Planner Studio*. ໂຄງການນີ້ຖືກເອີ້ນວ່າ *CSV Import*. `Task Type` ທີ່ບໍ່ແມ່ນລະຫັດຄົງທີ່ໃດໆ (ເຊັ່ນ `CONSTRUCTION` ຫຼື `INSTALLATION` ທີ່ແອັບຂຽນເອງ) ກາຍເປັນປະເພດໜ້າວຽກກຳນົດເອງ ພາຍໃຕ້ *ຈາກໂຄງການນີ້*, ບໍ່ແມ່ນໃນ *ປະເພດໜ້າວຽກຂອງຂ້ອຍ*; ດ້ວຍ `OPS Custom Task Type ID` id ຂອງປະເພດກຳນົດເອງຖືກເກັບໄວ້.

**ບັນທຶກ** — ບໍ່ໄດ້.

**ສົ່ງອອກ** — ໄດ້, ເປັນ *CSV (;)* (*ການສົ່ງອອກຕາຕະລາງແບບທົ່ວໄປ. ລວມທຸກວຽກພ້ອມວັນທີ ແລະ ໄລຍະເວລາ.*), ໃນກາດ *CSV (ຂັ້ນດ້ວຍຈໍ້າຈຸດ ;)*. ໄຟລ໌ໃຊ້ຈໍ້າຈຸດເປັນຕົວແຍກ, ເປັນ UTF-8 ມີ BOM ແລະ ມີຫົວຖັນເປັນພາສາອັງກິດ.

**ສິ່ງທີ່ຕິດໄປນຳ** — ສຳລັບແຕ່ລະໜ້າວຽກ ມີຖັນເຫຼົ່ານີ້: `OPS Task ID`, `WBS`, `Outline Level`, `Name`, `Duration (days)`, `Start`, `Finish`, `Predecessors`, `Task Type`, `OPS Custom Task Type ID`, `Status`, `Completion (%)`, `Actual Start`, `Actual Finish`, `Critical`, `Total Float` ແລະ `Description`. ເປີເຊັນສຳເລັດເປັນຈຳນວນເຕັມ.

**ສິ່ງທີ່ບໍ່ຕິດໄປນຳ** — ຊັບພະຍາກອນ, ການມອບໝາຍ, ປະຕິທິນ, ເງື່ອນໄຂ, ກຳນົດສົ່ງ, ແຜນຫຼັກ ແລະ ວັນທີສະຖານະ. ຖ້າວັນທີຢູ່ໃນມຸມມອງ *ວັນທີຕາມທີ່ບັນທຶກ*, ການສົ່ງອອກຈະເຮັດໃຫ້ `Critical` ແລະ `Total Float` ວ່າງເປົ່າ ສຳລັບໜ້າວຽກທີ່ໄຟລ໌ຕົ້ນສະບັບບໍ່ໄດ້ບັນທຶກຂໍ້ມູນນັ້ນ.

## ໃບຄວາມຄືບໜ້າ (Excel ແລະ CSV)

**ເປີດ** — ໄດ້, ດ້ວຍ *ໄຟລ໌ › ນຳເຂົ້າ* (*ອັບເດດຄວາມຄືບໜ້າຈາກສະເປຣດຊີດ*) ຫຼື ດ້ວຍປຸ່ມທີ່ຊື່ດຽວກັນ ໃນກຸ່ມ *ຄວາມຄືບໜ້າ* ຂອງແຖບເຄື່ອງມື ໃນ *ການວາງແຜນ*, *ຕາຕະລາງ* ແລະ *ລາຍງານ*. ແອັບອ່ານ `.xlsx` ແລະ `.csv` ໄດ້ເຖິງ 16 MB ແລະ 50,000 ແຖວ. ນີ້ບໍ່ເປີດໂຄງການ: ມັນອັບເດດຄວາມຄືບໜ້າຂອງໂຄງການທີ່ເປີດຢູ່ຂອງທ່ານ. ເບິ່ງ [ການນຳເຂົ້າຄວາມຄືບໜ້າຈາກສະເປຣດຊີດ](docs://howto-voortgang-importeren).

**ບັນທຶກ** — ບໍ່ໄດ້.

**ສົ່ງອອກ** — ໄດ້, ເປັນ *ໃບຄວາມຄືບໜ້າ (Excel)* (*ຄວາມຄືບໜ້າ (Excel)* ໃນລາຍການ) ແລະ *ໃບຄວາມຄືບໜ້າ (CSV)* (*ຄວາມຄືບໜ້າ (CSV)*). ຊື່ເລີ່ມຕົ້ນ: *ຊື່ໂຄງການ-ຄວາມຄືບໜ້າ*. ປຸ່ມ *ສົ່ງອອກໃບຄວາມຄືບໜ້າ* ໃນກຸ່ມ *ຄວາມຄືບໜ້າ* ດຽວກັນ ສ້າງໃບ Excel ໃນການກົດຄັ້ງດຽວ. ໃບ Excel ມີຄວາມກວ້າງຖັນຄົງທີ່, ຊ່ອງທີ່ລັອກ ແລະ ການກວດວັນທີ; ໃບ CSV ມີເນື້ອຫາດຽວກັນເປັນຂໍ້ຄວາມທຳມະດາ.

**ສິ່ງທີ່ຕິດໄປນຳ** — ຖັນ `OPS Task ID`, `WBS`, `Name`, `Start`, `Finish`, `Completion (%)`, `Actual Start` ແລະ `Actual Finish`. ເມື່ອນຳເຂົ້າ ແອັບໃຊ້ `Completion (%)`, `Actual Start` ແລະ `Actual Finish`; `Start` ແລະ `Finish` ໃຊ້ພຽງເພື່ອຮັບຮູ້ຮູບແບບວັນທີ ແລະ ບໍ່ປ່ຽນແຜນງານຂອງທ່ານ. ແອັບເຊື່ອມແຖວກັບໜ້າວຽກດ້ວຍ `OPS Task ID`, ຫຼືຖ້າບໍ່ມີ ດ້ວຍລະຫັດ WBS ທີ່ບໍ່ຊ້ຳກັນ.

**ສິ່ງທີ່ບໍ່ຕິດໄປນຳ** — ທຸກຢ່າງນອກຖັນເຫຼົ່ານີ້: ໄລຍະເວລາ, ສາຍສຳພັນ, ຊັບພະຍາກອນ ແລະ ສ່ວນທີ່ເຫຼືອຂອງແຜນງານຂອງທ່ານ. ໜ້າວຽກຫຼັກ ບໍ່ໄດ້ຮັບຄວາມຄືບໜ້າຈາກໃບ.
