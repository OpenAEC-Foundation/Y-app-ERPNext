# 约束和截止日期

砖块要到 6月21日 才送达。许可证还没有批下来。屋顶必须在建筑业假期之前封顶。关系记录的是一个任务要等待另一个任务，但日期方面的约定不会由工作的先后顺序决定。约束和截止日期就是为此而设。在本文中，你将了解每种类型的作用、任务何时移动、何时只有浮时发生变化、什么是硬性钉住，以及应用如何报告冲突。

这些规则和示例适用于新项目，计算配置文件为 *Open Planner Studio*，工作周为周一至周五。

## 概念

**约束**是对单个任务的日期限制，与该任务的关系无关。这种限制可以以两种方式起作用：

- 它**推动**：任务不得早于该日期开始或完成。如果由于其关系，任务会更早开始，它就会移到该日期。
- 它**守住**：任务最迟必须在该日期开始或完成。应用不移动任何东西。如果计划达不到该日期，该任务及其前面的链条的**浮时**就会变为负值。浮时是任务在项目完成日期移动之前还有的余量；负值表示，按计划来看你已经迟了（见 [关键路径和浮时](docs://uitleg-kritiek-pad)）。

**截止日期**是一种较简单的守住方式：它是任务完成的目标日期，任务本身不会因此被移动。

所有约束都是**软性**的：即使未达到某个日期，计算仍会继续。只有一个例外，即**硬性钉住**，它会覆盖关系。下文将对此作进一步说明。

## 应用如何计算

### 八种类型

你在 *属性* 面板中，于 *限制* 处选择类型。每种类型的计算方式如下：

- *越早越好 (ASAP)*：无限制。这是默认值：任务在关系允许的情况下尽早开始。
- *越晚越好 (ALAP)*：任务尽可能晚地移动，但不会使后续任务必须更晚开始。因此，它会用完自由浮时。如果之后仍有总浮时，因为其后续任务本身还有余量，它保持非关键；如果总浮时也用完了，它就算作关键。
- *不得早于…开始 (SNET)*：开始的下限。如果任务会更早开始，它会移到该日期；如果该日期早于关系所允许的时间，约束不起任何作用。
- *不得早于…完成 (FNET)*：与上面相同，但针对任务的完成。
- *不得晚于…开始 (SNLT)* 和 *不得晚于…完成 (FNLT)*：开始或完成的上限。它们不移动任何东西。如果未达到该上限，应用会报告违反限制，并且浮时变为负值。
- *必须开始于 (MSO)* 和 *必须完成于 (MFO)*：同时是下限和上限。如果该日期晚于关系所要求的时间，任务就会移到该日期。如果该日期早于关系所允许的时间，任务会留在关系所决定的位置，浮时变为负值。

如果某个日期落在星期六、星期日或休息日，应用会将其视为工作日：下限（SNET、FNET）取下一个工作日，上限（SNLT、FNLT）取上一个工作日。

### 负浮时的含义

上限的作用是反向的。如果约束使任务的最晚日期早于其最早日期，总浮时就会变为负值。它前面的任务也是如此：如果砌砖最迟必须在 6月11日（星期五）开始，而又不能早于 6月14日（星期一）开始，那么砌砖之前的任务也会晚一个工作日。所有负浮时的任务都是关键任务；其原理见 [关键路径和浮时](docs://uitleg-kritiek-pad)。

上限不会使任务条移动。你可以在负值的 *总浮时* 中看到冲突，在任务条上方的红色菱形中看到，在状态栏的提示中看到（例如 *1 个限制被违反*），也可以在 *警告* 面板中看到。

### 硬性钉住

对于 MSO 和 MFO，会出现复选框 *强制（钉住逻辑）*。勾选后，即使前置任务到那时仍未完成，你也会将任务固定在该日期。关系会被覆盖：

- 任务位于该日期（使用 MSO 时它在该日期开始，使用 MFO 时它在该日期完成），并与其前置任务重叠。
- 前置任务的浮时变为负值。一旦关系会让任务晚于钉住的日期开始，应用就会报告违反限制。被钉住的任务本身保持 0 浮时。
- 后续任务从被钉住的任务开始计算。因此，即使其前面的逻辑尚未完成，它们也可能比没有钉住时更早开始。在下面的示例中，项目的结束因此提前了三个工作日。

你第一次开启钉住时，应用会显示简短说明：硬性钉住会覆盖关系，任务条固定在该日期，即使前置任务尚未完成。

### 次要约束

任务有一个主要限制。如果你还想要第二个限制，例如任务不得早于 6月14日 开始，并且必须在 6月17日 前完成，你就添加一个**次要约束**。它必须是真正的限制（SNET、FNET、SNLT 或 FNLT），并且与主要限制的方向相反：下限（SNET 或 FNET）配上限（SNLT 或 FNLT）。因此，SNET 与 SNLT 可以同时使用，SNET 与 FNET 不可以。应用会用红色标出其他组合，并给出原因，例如 *主要限制和次要约束不能约束同一侧。* 对于 ASAP、ALAP、MSO、MFO 和硬性钉住，不允许使用次要约束。

### 截止日期

截止日期是任务上与约束并列的另一个日期。它是完成日期的上限：它不移动任何东西，但如果任务未能按时完成，浮时就会变为负值。随后，应用会在 *警告* 面板中报告 *已错过截止日期 … — 最早完成 …*，状态栏会统计错过的截止日期数。在 Gantt 中，截止日期上会有一个向下的箭头：任务按时完成时为绿色，一旦迟到就变为红色。落在星期六的截止日期，算到其前一个星期五为止（含该星期五）。

对于浮时，截止日期的作用与 FNLT 相同。区别在于使用方式。截止日期是你想要守住的目标日期；它独立于约束，因此一个任务可以同时有约束和截止日期。FNLT 是一种约束：违反时会显示为违反限制，而不是错过截止日期。

### 约束不起作用的情况

- 在**阶段**（摘要任务）上，约束或截止日期不起作用：应用会根据阶段中的任务进行计算。请将其设置在任务本身上。
- 已有实际开始日期或进度的任务，会保留该开始日期。一个日期较晚的 SNET 不会移动它。
- 在有前置任务的任务上**输入开始日期**，并不会成为固定开始：前置任务仍然决定开始时间。因此，应用会将其转为以你输入的日期为准的 SNET，无论是在 *属性* 面板中、在 *编辑任务* 中、在表格中，还是你在 Gantt 中移动任务条时。应用会告诉你这一点。如果该任务已有其他约束（例如 ALAP 或 MSO），应用不会采用新的开始日期，并同样会告诉你；这时请更改该约束。

所有更改只有在 **计算**（F5）之后才会显示。

## 实例演示

该示例是一个房屋扩建的小型网络。它从 2027年6月7日（星期一）开始：

- *Groundwork*（3 个工作日）：6月7日（星期一）至 6月9日（星期三）。
- *Pour foundation* (2)：6月10日（星期四）和 6月11日（星期五）。
- *Brickwork* (5)：6月14日（星期一）至 6月18日（星期五）。
- *Roofing* (3)：6月21日（星期一）至 6月23日（星期三）。
- *Scaffolding* (2)：排在 *Pour foundation* 之后，*Roofing* 之前。它在 6月14日（星期一）和 6月15日（星期二）进行，并有 3 个工作日的浮时。

关键路径是 *Groundwork*、*Pour foundation*、*Brickwork* 和 *Roofing*。项目在 6月23日（星期三）完成。在 *Brickwork* 上添加一个约束，会有什么变化？

- **SNET 6月21日（星期一）**（砖块只在那时才送达）：*Brickwork* 从 6月21日（星期一）进行到 6月25日（星期五），*Roofing* 从 6月28日（星期一）进行到 6月30日（星期三）。项目在 6月30日（星期三）完成。*Groundwork* 和 *Pour foundation* 现在有 5 个工作日的浮时，不再是关键任务；*Scaffolding* 有 8 个工作日。
- **SNET 6月9日（星期三）**：没有影响。关系本来就只允许 *Brickwork* 在 6月14日（星期一）开始。
- **SNLT 6月16日（星期三）**：没有影响。*Brickwork* 在 6月14日（星期一）开始，并轻松满足该限制。
- **SNLT 6月11日（星期五）**：太紧。*Brickwork* 仍在 6月14日（星期一）开始，晚了一个工作日。*Groundwork*、*Pour foundation* 和 *Brickwork* 的浮时变为 −1 个工作日，应用会报告 *限制 不得晚于…开始 (SNLT) 11-06-2027 被逻辑覆盖（负浮时）*。没有任何东西移动。
- **MSO 6月16日（星期三）**（不使用硬性钉住）：*Brickwork* 移到 6月16日（星期三），并于 6月22日（星期二）完成。*Roofing* 从 6月23日（星期三）进行到 6月25日（星期五），项目于 6月25日（星期五）完成。
- **MSO 6月11日（星期五）**（不使用硬性钉住）：该日期早于关系所允许的时间。*Brickwork* 仍在 6月14日（星期一）开始，浮时变为 −1，与 SNLT 的情况相同。
- **MSO 6月9日（星期三）并使用硬性钉住**：*Brickwork* 在 6月9日（星期三）开始，并于 6月15日（星期二）完成，而 *Pour foundation* 仍进行到 6月11日（星期五）。*Roofing* 从 6月16日（星期三）进行到 6月18日（星期五）：项目比没有钉住时提前三个工作日完成。*Groundwork* 和 *Pour foundation* 的浮时变为 −3 个工作日。

以下是在其他任务上设置约束或截止日期的情况：

- **在** *Scaffolding* **上设置 ALAP**：任务移到 6月17日（星期四）和 6月18日（星期五），即 *Roofing* 之前的最晚时刻。*Roofing* 是它唯一的后续任务，其余量正好是 3 个工作日的浮时；现在这些浮时已用完，*Scaffolding* 成为关键任务。
- **在** *Scaffolding* **上设置 SNET 6月19日（星期六）**：该限制按 6月21日（星期一）计算。*Scaffolding* 在 6月21日（星期一）和 6月22日（星期二）进行，*Roofing* 随之移到 6月23日（星期三）至 6月25日（星期五）。
- **在** *Roofing* **上设置截止日期 6月18日（星期五）**：没有任何东西移动，*Roofing* 仍在 6月21日（星期一）至 6月23日（星期三）进行。*Groundwork*、*Pour foundation*、*Brickwork* 和 *Roofing* 的浮时变为 −3 个工作日，应用会报告 *已错过截止日期 18-06-2027 — 最早完成 23-06-2027*。*Scaffolding* 的浮时保持 0 个工作日，也成为关键任务。
- **在** *Brickwork* **上设置 SNET 6月21日（星期一）**，**在** *Roofing* **上设置截止日期 6月25日（星期五）**：约束把 *Brickwork* 推迟了一周，截止日期则显示 *Roofing* 在 6月30日（星期三）迟到。*Brickwork* 和 *Roofing* 的浮时变为 −3 个工作日；*Groundwork* 和 *Pour foundation* 保持 2 个工作日。

在教程 3 中，你自己在教程项目里设置约束和截止日期，并看到计划如何移动。

## 后果和常见误解

**“约束会移动任务。”** 只有 SNET、FNET、MSO 和 MFO 能使任务晚于其关系所决定的时间，而 ALAP 可以在其自由浮时内把任务往后推。SNLT 和 FNLT 从不移动任何东西：它们只发出警告。要达到该日期，就必须缩短它前面的链条。

**“负浮时是应用的故障。”** 这是一个信号，表示计划与你的日期约定相冲突。你可以缩短链条、放宽约定，或有意接受这个冲突来解决它。

**“硬性钉住可以解决冲突。”** 硬性钉住会掩盖冲突：任务位于该日期，但其前置任务还没有为此准备好，而后续任务却仿佛它们已经准备好那样计算。只在日期确实固定时使用它，例如法定交付日期，而不要把它当作让任务落在某个日期上的手段。

**“我只要输入开始日期就行。”** 对于有前置任务的任务，这会变成 SNET。如果该日期早于前置任务所允许的时间，它不会起任何作用。

**“截止日期还是 FNLT？”** 对于你想守住的目标日期，选择截止日期；对于确实是计划边界条件的日期，选择约束。

**“在阶段上设置约束。”** 这不起作用。请将其设置在任务本身上。
