# 记录的日期

你从 Primavera 或 MS Project 打开一个计划，日期与你在该软件中看到的不同。导入出错了吗？通常没有。在本文中，你会了解：应用为什么自动重新计算，何时显示文件中的日期，此时哪些内容保持为空，以及如何返回应用自己的计算。文末的示例跟踪两个任务经历整个过程。

## 概念

计划文件包含两类数据。第一类是逻辑：任务、工期、关系、日历和约束。第二类是原软件根据这些内容自行计算出的日期。打开文件时，Open Planner Studio 使用逻辑并自行计算。因此，文件中的日期不是输入数据。

如果应用自己的计算得出的日期与文件所示不同，你无法判断哪一方正确。文件可能缺少原软件所用的逻辑。原软件在某些方面的计算也可能与应用不同。因此，应用可以显示**记录的日期**：即原软件写入文件的日期。这样，你就能与你在原软件中看到的内容进行比较。

## 应用如何处理

### 应用使用哪个计算配置文件

应用按**计算配置文件**计算。计算配置文件是一组计算规则（约定），例如决定应用如何处理任务计划的开始日期和约束。参见 [计算配置文件和约定](docs://uitleg-rekenprofielen)。应用内置三个配置文件：*Primavera P6*、*Microsoft Project* 和 *Open Planner Studio*。`.xer` 文件以 *Primavera P6* 打开，`.mpp` 文件以 *Microsoft Project* 打开。CSV、MS Project XML 和 Primavera P6 XML 以 *Open Planner Studio* 打开。项目的配置文件位于 *文件 › 项目信息* 中的 *计算配置文件和选项* 下。应用保存的 IFC 文件会保留其配置文件。

### 应用何时进行比较

打开文件时，应用会记录文件的内容，并将其与自身的计算结果进行比较。比较适用于：

- Primavera 文件（`.xer`）和 Primavera P6 XML；
- MS Project XML 和 MS Project 文件（`.mpp`）；
- 来自其他程序的 IFC 文件，针对文件中含有最早日期的任务；
- 应用自身保存、且记住了其来源的 IFC 文件。下文说明何时属于这种情况。

应用从不比较 CSV 文件：CSV 中的开始日期是输入数据，而不是计算结果。未记住来源的、应用自身保存的 IFC 文件同样不作比较。

如果没有任何任务不同，你不会察觉任何变化。如果你正在导入的文件中至少有一个任务不同，应用会立即开启此视图。

对于 Primavera 文件，应用按计算配置文件 *Primavera P6* 计算。这会将文件中计划的开始日期保留为最早开始。因此，文件中晚于关系所要求日期、但在文件中也有计划的任务会保持原位：此时没有差异。

### 你看到什么

功能区下方有一个提示栏：*你正在查看文件中记录的日期；重新计算将使 4 个任务偏移。* 若来源为 Primavera（`.xer` 或 Primavera P6 XML），则显示 *你正在查看 Primavera 记录的进度计划；重新计算将使 1 个任务偏移。* 栏的右侧是 *重新计算* 按钮。该栏没有叉号。

还有一条消息：*显示文件中记录日期（未重新计算）的任务：4 个。* 只有 `.xer` 文件才显示 *显示 Primavera 记录日期（未重新计算）的任务：1 个。* 对于文件中记录了日期的每个任务，*属性*面板中都会显示一个标记：来源为 Primavera 时为 *显示 Primavera 为此任务记录的日期*，其他来源时为 *显示文件中记录的此任务日期*。Gantt、任务表和状态栏显示的都是文件中的日期。

### 此视图中保持为空的内容

在此视图中，应用不做任何计算。它只显示文件中记录的内容。因此，只有文件包含浮时和关键路径时，你才会看到它们。如果文件没有记录关键任务，状态栏会显示 0 个关键任务。这并不能说明原软件中的关键路径。只有通过计算才能得出的内容，在此视图中不存在：例如驱动计划的关系、违反限制的约束、顺序错误的任务和近关键任务。

如果文件没有为某个任务记录全部数据，你会在*属性*面板中看到标记 *记录数据部分不完整——请查看最迟/时差列*。在 CSV 导出中，此类任务的 *关键* 和 *总浮时* 列保持为空，而不是填入编造的零。

### 离开此视图

你可以通过两种方式离开此视图：

- 点击提示栏中的 *重新计算*，或选择 *计算*（F5）。应用按照自身规则计算。
- 更改可能改变日期的内容，例如任务的工期或新增任务。即使 *自动计算* 已关闭，应用也会离开此视图并立即重新计算。更改名称不会这样：此视图保持开启。

来自资源库的日历更改会保持此视图开启，文件中的日期也保持不变，但会更新提示栏中的数字。

离开后，没有按钮可以切换回此视图。紧接在重新计算或此类编辑之后，Ctrl+Z 可以将其恢复。否则，你可以重新打开源文件。若来源为 `.xer`，则打开你在重新计算后保存、但未编辑过的 IFC 文件，同样会再次开启此视图。

### 崩溃恢复

如果你在崩溃前处于此视图中，恢复项目后此视图保持开启。处于活动状态的项目显示与之前相同的提示栏。位于另一个标签页上的项目会显示不带数字的提示栏：*你正在查看文件中记录的日期，尚未重新计算。* 参见 [从崩溃中恢复](docs://howto-herstellen-na-een-crash)。

### 保存与重新打开

如果你在使用此视图时保存，应用会将显示的日期连同来源格式写入 IFC 文件。如果你之后再次打开该 IFC 文件，且自导入后未编辑过，此视图会再次开启，且不会显示新消息。

如果你在此期间编辑并保存过，结果取决于来源。对于 Primavera 文件，IFC 文件会同时保留原始 `.xer`。随后，应用会再次比较并提供此视图：*重新计算使 2 个任务中的 1 个偏离了文件中记录的日期。* 同时出现 *显示记录的日期* 按钮和一个叉号。在每个偏离的任务上，*属性*面板都会显示标记 *偏离记录的日期*。*显示记录的日期* 会开启此视图；Ctrl+Z 可撤销该操作。叉号会隐藏此提示。

对于 MS Project XML、`.mpp`、Primavera P6 XML 或来自其他程序的 IFC 文件，IFC 文件不保留来源。如果你编辑并保存此类项目，重新打开时应用不再进行比较。

## 示例：扩建

假设你打开一个 Primavera 文件 *Uitbouw*（扩建），其中有两个任务，日历中没有假日。在 2027年，5月6日是耶稣升天节，5月17日是圣灵降临节星期一：如果日历中设有假日，日期会有所不同。*Fundering storten*（浇筑基础）需要 5 个工作日，*Metselwerk*（砌砖）需要 10 个工作日，Metselwerk 通过完成-开始关系接在 Fundering 之后。文件记录的是：Fundering 从 2027年5月3日（星期一）到 5月7日（星期五）；Metselwerk 从 2027年5月17日（星期一）到 5月28日（星期五）。这比关系允许的最早开始晚了一周。文件中 Metselwerk 计划的开始日期是 2027年5月10日（星期一）。

打开后，你会立即看到文件中的日期。状态栏显示 *结束：28-05-2027* 和 *关键路径：2 个任务，20 个工作日*。提示栏报告重新计算时有 1 个任务不同，两个任务都显示 *显示 Primavera 为此任务记录的日期*。

点击 *重新计算* 后，Fundering 保持在 5月3日至 7日。Metselwerk 现在从星期一 5月10日开始，即 Fundering 结束后的第一个工作日，并于星期五 5月21日完成。计划于 2027年5月21日结束，跨越 15 个工作日，而不是 20 个。关键路径由同样的 2 个任务组成。

如果情况不同呢？

- 如果文件中 Metselwerk 也计划在星期一 5月17日，计算配置文件 *Primavera P6* 会保留该开始日期。计算结果为 5月17日至 28日，没有差异，此视图不会开启。
- 你在此视图中新增一个任务：同样会重新计算。Metselwerk 移至 5月10日至 21日。
- 你在此视图中保存，然后不做编辑直接重新打开 IFC 文件：Metselwerk 回到 5月17日至 28日。
- 你重新计算，保存后不再编辑，然后重新打开 IFC 文件：此视图再次开启，Metselwerk 位于 5月17日至 28日。
- 你编辑、保存并重新打开：应用会提供此视图，并显示 *重新计算使 2 个任务中的 1 个偏离了文件中记录的日期。* Metselwerk 显示 *偏离记录的日期*。

## 后果与常见误解

**差异不是导入错误。**应用按照自身规则计算。对于 `.xer`，使用计算配置文件 *Primavera P6*；对于 `.mpp`，使用 *Microsoft Project*；对于 CSV、MS Project XML 和 Primavera P6 XML，使用 *Open Planner Studio*。原软件中的日期为何不同，原因可能在文件中，也可能在原软件中。此视图会告诉你日期*有*差异。

**此视图不是计算结果。**应用没有计算这些日期。不要直接把它们当作你自己计划的结果。

**在此视图中保存会保留源软件的日期。**此时 IFC 文件保存的是原软件所记录的内容，而不是应用会计算出的结果。

**并非每次导入都会出现 *显示记录的日期* 按钮。**打开新文件时，此视图已经开启。该按钮只会在重新打开一个来源为 Primavera 的 IFC 文件时出现，而且你自导入后已编辑过该文件。
