# 提供反馈

目标：报告错误或提出想法，可选择附加截图，使其最终成为 GitHub 上的议题。

## 何时需要此操作

计划计算出你不理解的结果，某个按钮没有做它应该做的事，或者你在应用中找不到某些内容。好的报告能帮助开发者找到问题。因此，应用会自行把版本、操作系统和语言放入你的报告中。你自己描述的内容决定开发者能否据此采取行动：你做了什么、你预期什么，以及实际发生了什么。

## 步骤

1. 点击窗口顶部的按钮 *发送反馈*。该按钮始终位于标题栏中。它的文字每十分钟会变化一次：*发送反馈*、*报告缺陷* 和 *提出新功能*。它始终是同一个按钮。*发送反馈* 窗口会打开。
2. 对于不按预期工作的情况，选择 *缺陷*。对于想法，选择 *功能请求*。默认选中 *缺陷*。
3. 填写 *标题*。如果没有标题，*发送到 GitHub* 按钮会显示为灰色。同时填写 *描述*，例如：你更改了哪个任务、你预期什么，以及你看到了什么。
4. 如果你想展示某些内容，开启 *附加截图*。然后应用会截取应用的画面（不含此窗口）。稍后你会看到一个小预览图。点击 *标注* 会打开编辑器，你可以在图片上添加箭头、矩形、手绘线条和文字。在编辑器中，你可以选择颜色，用 *撤销* 撤回上一步操作，或用 *清除全部* 重新开始。满意后，点击 *完成*。
5. 点击 *发送到 GitHub*。
6. 没有附加截图？那么用于创建新议题的 GitHub 页面会直接在浏览器中打开。请继续第 8 步。
7. 附加了截图？那么你会先看到 *即将完成 — 截图已复制到剪贴板。* 的提示，其中有四个步骤。点击 *确定，前往 GitHub*，在议题页面的大文本区域内单击，然后按 Ctrl+V（Mac 上按 Cmd+V）。图片随即上传，并显示在文本中。
8. 在议题页面底部，点击 *提交新议题*。只有这样，你的报告才会发送。如果尚未登录，请先登录 GitHub。

在议题页面上，你的标题和描述已经填好。应用会建议标签 *bug* 或 *enhancement*，并在你的描述下方添加一行，内容包括类型、Open Planner Studio 的版本、你的操作系统和应用的语言。

## 常见问题及应用的处理方式

**应用不会自行发送任何内容。** *发送到 GitHub* 只会打开已填好内容的议题页面。如果你没有点击 *提交新议题* 就关闭该页面，则没有任何报告被提交。为此，你需要一个 GitHub 账户。

**你的报告会出现在 GitHub 上。** 不要在报告中放入你不想分享的内容。截图也是如此：图片会显示截图时应用中所有可见的内容，例如你项目中的任务名称和资源。应用会在你开启 *附加截图* 时截图。因此，在开启之前请确保屏幕内容正确，并去掉你不想展示的内容。

**无法粘贴。** 截图也会以文件形式保存在你的电脑上。在桌面应用中，窗口会提示路径：*无法粘贴？截图也已保存到* 该路径 *— 将该文件拖入文本区域。* 在浏览器中，应用会将图片下载为 `feedback-` 加编号、文件后缀为 `.png` 的文件。你可以在下载文件夹中找到它，并将其拖入文本区域。

**截图失败。** 窗口显示 *截图失败。您仍然可以在没有截图的情况下发送反馈。* 复选框会取消勾选，你可以不带图片发送报告。

**你已输入大量内容，却不小心点击了窗口外部。** 这不会关闭窗口，因此你的文本会保留。按 Esc 或 *取消* 会关闭窗口，此时你的文本会丢失。
