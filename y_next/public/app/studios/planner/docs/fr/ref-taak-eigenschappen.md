# Boîte de dialogue de tâche et panneau des propriétés

Vous pouvez modifier une tâche à deux endroits : dans la fenêtre *Modifier la tâche* et dans le panneau *Propriétés*. Ils partagent presque tous les champs. Cet article indique pour chaque champ ce qu'il fait, quelle est la valeur par défaut et ce que vous remarquez. Vous trouverez comment créer et configurer une tâche dans [Ajouter des tâches et des jalons](docs://howto-taken-en-mijlpalen-toevoegen). La raison du résultat du calcul se trouve dans [Chemin critique et marge](docs://uitleg-kritiek-pad).

## Les deux emplacements

- **Modifier la tâche** — la fenêtre de la première tâche sélectionnée. Ouvrez-la avec F2, par un double-clic sur une barre dans le Gantt, ou par un clic droit sur une tâche dans le Gantt ou le tableau, puis en choisissant *Modifier...*. Vos modifications restent dans un brouillon jusqu'à ce que vous cliquiez sur *Enregistrer* (Entrée). *Annuler* (Échap) les supprime. *Enregistrer* est désactivé tant que le nom est vide. Un enregistrement compte pour une seule étape sous *Annuler*. Cela vaut aussi pour ce que vous avez fait dans les rubriques *Règle de travail*, *Dépendances*, *Affectations* et *Codes et champs*. Ces rubriques agissent déjà sur le projet pendant que vous modifiez, et *Annuler* les inverse.
- **Propriétés** — le panneau dans la colonne de droite, pour la tâche active. Chaque modification prend effet tout de suite. Des modifications successives du même champ comptent pour une seule étape sous *Annuler*. Sans tâche, il affiche *Sélectionnez une tâche pour afficher les propriétés.* Activez ou désactivez-le avec *Affichage › Panneaux › Propriétés*. Par défaut : activé. Le panneau se trouve à côté du Gantt et dans l'onglet *Tableau*. Il ne se trouve pas dans *IFC* et *Rapport*, ni sous le panneau des ressources complet.

Seulement dans la fenêtre : *Tâche parente* et les boutons *Enregistrer* et *Annuler*. Seulement dans le panneau : la corbeille *Supprimer la tâche*, le bouton *Calculer* en bas, la rubrique *Interruptions*, les trois marqueurs sous *Règle de travail* (longue période non ouvrée, MS Project, dates enregistrées), ainsi que l'ajout de relations et le saut vers une tâche liée dans *Dépendances*. Tous les autres champs se trouvent aux deux endroits. La fenêtre affiche *Dépendances*, *Affectations* et *Codes et champs* seulement pour une tâche existante.

Si vous avez modifié quelque chose qui touche aux dates, appuyez sur *Calculer*. Le calcul ne se lance pas tout seul, sauf si *Calculer automatiquement* est activé.

## Général

- **Nom** (dans la fenêtre *Nom \**) — le nom de la tâche dans le Gantt, le tableau et les rapports. Obligatoire : un nom vide n'est pas conservé. Par défaut pour une nouvelle tâche : *Nouvelle tâche*.
- **Code WBS** — le code de structure de la tâche, par exemple `RB-301`. Obligatoire. Avec *Planification › Structure › WBS auto*, le champ est désactivé (info-bulle : *Les codes WBS sont numérotés automatiquement (Planification → Structure)*), car l'application gère alors les codes.
- **Description** — texte libre. Sans effet sur le calcul. Vous pouvez l'afficher comme colonne *Description* dans le tableau.
- **Type** — le type de tâche. La liste contient les groupes *Types intégrés* (*Construction*, *Installation*, *Démolition*, *Logistique*, *Inspection*, *Déplacement*, *Rénovation*, *Maintenance*), *Mes types de tâche* et *De ce projet*. *Autre* n'apparaît que si la tâche a déjà ce type. En bas se trouvent *+ Nouveau type de tâche…* et *Gérer les types de tâche…*. Par défaut : le type de la tâche parente, sinon *Construction* (mode Construction activé, par défaut) ou *Autre*. Effet : aucun effet sur le calcul. Vous pouvez grouper et filtrer selon ce type, et colorer les barres selon ce type. L'application garde un type personnalisé sur votre appareil. Quand vous le choisissez, une copie entre dans le projet (*De ce projet*). Si vous saisissez à *+ Nouveau type de tâche…* un nom qui existe déjà dans *Mes types de tâche*, même avec d'autres majuscules, l'application ne crée pas de second type. Elle choisit le type existant. Dans *Gérer les types de tâche…*, vous modifiez ou supprimez seulement vos propres types. Un nom vide ou un nom déjà existant n'est pas conservé. Si vous supprimez un type que le projet ouvert utilise, l'application demande d'abord confirmation. La copie dans le projet reste. Un type sous *De ce projet*, par exemple venant du fichier de quelqu'un d'autre, entre dans votre propre liste seulement si vous cliquez sur *Ajouter à mes types de tâche* dans *Gérer les types de tâche…*.
- **Calendrier** — le calendrier dans lequel la tâche compte sa durée, sa date de fin et sa marge. Par défaut : *Calendrier du projet : {name}*. Effet : une tâche avec son propre calendrier travaille sur d'autres jours que le calendrier du projet. Après une modification, *Calculer* recalcule les dates. Voir [Calendriers et jours ouvrés](docs://uitleg-kalenders).
- **Tâche parente** (seulement dans la fenêtre) — déplace la tâche sous une autre tâche. Par défaut : la tâche parente actuelle. *- Aucun (racine) -* place la tâche au niveau le plus haut. Un choix qui créerait un cycle dans les relations est refusé quand vous cliquez sur *Enregistrer*, avec un message. La fenêtre reste ouverte.

## Notes

- **Notes** — une liste de contrôle sur la tâche. *Ajouter une note* ajoute une ligne. La coche (*Terminé*) la raye. La corbeille (*Supprimer*) la supprime. Sans lignes, il affiche *Pas encore de notes.* Sans effet sur le calcul. La colonne *Notes* du tableau les affiche avec ✓ ou ○ devant.

## Jalon

- **Jalon** — fait de la tâche un jalon. Par défaut : désactivé. Effet : la durée devient 0. L'application refuse ce choix pour une tâche récapitulative (une tâche avec des sous-tâches) et pour une tâche avec des affectations de ressources. Un message l'indique. Supprimez d'abord les affectations. Si vous décochez à nouveau, *Type de jalon* et *Obligatoire (contractuel)* disparaissent.
- **Type de jalon** (seulement pour un jalon) — *Automatique*, *Jalon de début* ou *Jalon de fin*. Par défaut : *Automatique*. Effet : un jalon de début se place au début d'un jour, et un jalon de fin à la fin. Avec *Automatique*, le jalon compte comme jalon de début quand il est prédécesseur, au début du jour.
- **Obligatoire (contractuel)** (seulement pour un jalon) — marque un jalon contractuel, par exemple une inspection ou une remise. Par défaut : désactivé. Effet : un repère pour le Gantt et les rapports. Il ne fixe pas de date. Pour fixer une date, utilisez une contrainte ou une échéance.

## Temps

- **Début** (dans la fenêtre *Date de début*) — affiche le début calculé. C'est la même date que la barre du Gantt et que la colonne *Début*, et non l'ancrage de planification brut. Obligatoire : un champ vide revient à la valeur précédente. Effet de la saisie : la nouvelle date devient l'ancrage planifié (colonne *Début planifié*). Si la tâche a un prédécesseur et n'a pas encore commencé, l'application enregistre le nouveau début comme contrainte *Début au plus tôt le (SNET)* à cette date. Elle déplace aussi une SNET existante. Un message l'indique. Après *Calculer*, la tâche ne commence donc pas plus tôt. S'il existe une contrainte autre que *Dès que possible (ASAP)* ou *Début au plus tôt le (SNET)*, l'application n'applique pas le début. Elle indique la contrainte qui détermine le début.
- **Durée** — la durée de travail de la tâche. Tapez `5d` pour des jours, ou `12h` ou `1h 30m` pour des heures. Un nombre sans unité compte dans l'unité de la tâche. Les jours sont toujours entiers. Les heures peuvent avoir une décimale. Une saisie non valide affiche *Saisissez un nombre entier de jours ou d'heures, par exemple 2d ou 12h.* Le champ revient alors à la valeur précédente. Par défaut pour une nouvelle tâche : 5 jours (un jalon : 0). Le champ est désactivé pour une tâche récapitulative, un hamac et un jalon de durée 0. Leur durée découle d'autres tâches, ou vaut zéro. Une tâche en heures est désactivée tant que *Activer la planification horaire* est désactivé. Il existe un bouton portant ce nom. Effet : après *Calculer*, la durée détermine la fin dans le calendrier de la tâche. Si la tâche a des ressources et une règle de travail, la règle décide si le travail ou les unités changent. Si la tâche est déjà en partie réalisée, l'application refuse une durée plus courte que le travail effectué. Voir [Jours et heures](docs://uitleg-dagen-en-uren).
- **Unité de durée** — un choix entre *Jours* et *Heures*, avec un bouton d'information à côté. Visible seulement quand *Activer la planification horaire* et *Autoriser la planification mixte jour/heure* sont activés. Ce dernier est activé par défaut quand la planification horaire l'est. Effet : quand vous choisissez une autre unité, l'application convertit la durée immédiatement si le résultat est exact. *Annuler* revient en arrière en une seule étape. Si le résultat n'est pas exact, l'unité reste et l'application l'indique. Un calendrier sans horaires de travail valides refuse le changement.
- **Règle de travail** — quelles deux grandeurs parmi durée, unités et travail restent fixes quand l'une des trois change. Choix : *Valeur par défaut du projet (Durée et unités fixes)*, *Durée et unités fixes*, *Durée et travail fixes*, *Travail fixe* et *Unités fixes*. Par défaut : la valeur par défaut du projet. Sous le champ figure ce que la règle protège (*Protégé : …*). Pour une tâche venant de MS Project, il affiche *Depuis MS Project : piloté par l'effort* ou *Depuis MS Project : non piloté par l'effort*. Le champ est visible seulement quand *Afficher les règles de travail et le travail* est activé (*Paramètres*, onglet *Planification*, rubrique *Calcul*). Il l'est aussi quand le fichier lui-même contient des règles de travail ou du travail enregistré. Il n'apparaît que pour une tâche ordinaire : pas pour une tâche récapitulative, un jalon, un hamac ni une tâche en temps écoulé. Voir [Règles de travail : durée, unités et travail](docs://uitleg-werkregels).

## Hamac

- **Hamac (durée dérivée)** — laisse la durée découler de deux autres tâches, au lieu d'avoir une durée propre. Par défaut : désactivé. Seulement pour une tâche ordinaire, donc pas pour un jalon ou une tâche récapitulative. Activé : *Driver de début* affiche les prédécesseurs avec une relation fin-début ou début-début. *Driver de fin* affiche ceux avec une relation fin-fin ou début-fin. Chacun est suivi de son type de relation. Sans driver de fin, l'application affiche *Aucun driver de fin (FF/SF) — l'intervalle revient à une longueur nulle.* et la durée vaut zéro. Voir [Créer un hamac](docs://howto-hammock).

## Contrainte et échéance

Sur une tâche récapitulative, une contrainte ou une échéance n'a aucun effet. Le calcul ne calcule que les tâches feuilles. Il déduit les dates d'une tâche récapitulative de ses sous-tâches.

- **Contrainte** — une limite de date pour la tâche. Choix : *Dès que possible (ASAP)*, *Le plus tard possible (ALAP)*, *Début au plus tôt le (SNET)*, *Début au plus tard le (SNLT)*, *Fin au plus tôt le (FNET)*, *Fin au plus tard le (FNLT)*, *Doit commencer le (MSO)* et *Doit finir le (MFO)*. Par défaut : *ASAP*, soit aucune contrainte. Si vous choisissez ASAP, toutes les contraintes de la tâche disparaissent. Si vous choisissez ALAP, la contrainte secondaire disparaît. Effet après *Calculer* : une limite déplace la tâche, ou rend la marge négative. Voir [Contraintes et échéances](docs://uitleg-constraints).
- **Date de contrainte** — la date qui correspond à la contrainte. Visible pour chaque contrainte sauf *ALAP*. Obligatoire. Une nouvelle contrainte reçoit le début planifié comme date.
- **Obligatoire (logique d'ancrage)** — seulement pour *MSO* et *MFO*. Par défaut : désactivé. Activé : la date est stricte. Elle remplace les relations et fixe la barre, même avant ses prédécesseurs. Une violation devient une marge négative en amont. La première fois que vous l'activez, une explication apparaît une seule fois.
- **Contrainte secondaire** et **Date secondaire** — une seconde limite. C'est seulement une de *SNET*, *FNET*, *SNLT* ou *FNLT*, ou *(aucun)*. Visible dès qu'il existe une contrainte principale qui n'est ni ASAP, ni ALAP, ni un ancrage strict. Elle est toujours souple. Une combinaison interdite reçoit une bordure rouge et une raison. Une contrainte secondaire ne peut pas être stricte. Elle ne peut pas être combinée avec MSO/MFO ou un ancrage strict, ni avec ASAP/ALAP. Elle doit être une borne. La principale et la secondaire ne peuvent pas borner le même côté. Une paire valide est par exemple SNET avec FNLT.
- **Échéance** — une date cible pour la fin. Vide = pas d'échéance. Effet : la tâche ne bouge pas à cause d'elle. Si la fin au plus tôt est plus tardive, la marge devient négative. L'application signale alors *Échéance … dépassée — fin au plus tôt …*.

## Avancement

- **Avancement (%)** — un curseur de 0 à 100. Par défaut : 0. Effet : au-dessus de 0, l'application complète un *Début réel* manquant. 100 complète la *Fin réelle*. Le statut suit : *Non démarrée* sans début réel, *En cours* avec un début réel, et *Terminée* avec une fin réelle. La durée restante (*Restant*) vaut durée × (1 − avancement). Elle est arrondie aux jours entiers pour une tâche en jours, et aux minutes entières pour une tâche en heures. Le travail réalisé est mesuré jusqu'à la date d'état. S'il n'existe pas encore de date d'état, l'application la fixe à aujourd'hui et l'indique. Pour une tâche récapitulative, le champ est désactivé. Son avancement découle de ses sous-tâches après *Calculer* (*Dérivé des sous-tâches : modifiez l'avancement à ce niveau. La tâche récapitulative suit après le calcul (F5).*).
- **Début réel** — la date à laquelle la tâche a vraiment commencé. Une date après la fin réelle ou après la date d'état est refusée. Si la tâche est planifiée pour ne commencer qu'après la date d'état et reçoit maintenant un avancement, la fenêtre demande *Indiquer le début réel*. Pour un jalon, il y a un seul champ *Date réelle* à la place de *Début réel* et *Fin réelle*.
- **Fin réelle** — la date à laquelle la tâche a vraiment été terminée. Renseigner ce champ met l'avancement à 100 et le statut à *Terminée*. L'effacer remet l'avancement à 0 et le statut à *En cours*. Les mêmes refus que pour *Début réel* s'appliquent.
- **Restant** — en lecture seule (pas pour un jalon) : la durée restante, dans l'unité de la tâche.

La fenêtre applique ces règles au brouillon. Elles ne comptent qu'après *Enregistrer*. Voir [Avancement, date d'état et référence](docs://uitleg-voortgang).

## Résultat CPM

- **Résultat CPM** — vue en lecture seule du dernier calcul : *Début au plus tôt*, *Fin au plus tôt*, *Début au plus tard*, *Fin au plus tard*, *Marge totale*, *Marge libre*, *Marge d’interférence* et *Chemin critique* (*Oui* ou *Non*). La marge est exprimée en jours ouvrés, avec deux décimales. Résultat périmé ou pas encore calculé ? Appuyez sur *Calculer*.

## Dépendances

- **Dépendances** — les relations de cette tâche, une ligne par relation. Chaque ligne contient la tâche liée (dans le panneau le code WBS, ou le nom s'il manque ; dans la fenêtre le nom). Une icône d'éclair apparaît si la relation est déterminante (*Relation déterminante*, après un calcul). Viennent ensuite le type de relation (*FS*, *SS*, *FF* ou *SF*), le décalage et une corbeille. Dans le panneau, le code WBS est un bouton : le survol affiche la tâche, et un clic y saute. Une petite marque devant le code indique le rôle : un rond doré pour un prédécesseur et un carré violet pour un successeur. Ce sont les mêmes couleurs que dans [Suivre un chemin](docs://howto-pad-traceren). Le rôle figure aussi dans le nom du bouton, pour un lecteur d'écran. Dans la fenêtre, c'est du texte simple. La rubrique n'apparaît que si la tâche a des relations.
- **Décalage** — tapez un nombre avec une unité : `2d` jours ouvrés, `3ed` jours calendaires, `2u` ou `2h` heures ouvrées, `3eu` ou `3eh` heures calendaires, `50%` un pourcentage de la durée du prédécesseur, `-25e%` un pourcentage en temps calendaire. Un signe moins en fait une avance. Sans unité, il compte en jours ouvrés. Une saisie non valide rend le champ rouge. Le champ revient alors à la valeur précédente. Voir [Relations et décalage](docs://uitleg-relaties).
- **Ajouter une relation** (seulement dans le panneau) — ouvre une ligne de brouillon. Sous *Direction*, choisissez *Prédécesseur* ou *Successeur*. Cherchez la tâche avec *Rechercher une tâche…* par code WBS ou par nom. Choisissez le type et le décalage, puis confirmez avec *Créer la relation* (ou *Annuler*). Un doublon, ou une relation avec le parent de la tâche, est refusé avec un message. La ligne reste.

## Interruptions

Uniquement dans le panneau, et non pour un jalon, une tâche récapitulative, un hamac, une tâche en temps écoulé, une tâche planifiée manuellement ou une tâche trop courte pour une interruption.

- **Interruptions** — interruptions du travail de la tâche. Une ligne par interruption : *après* (quantité de travail avant l'interruption), *pause* (la durée) et l'unité (*jours ouvrés*, pour une tâche en heures *heures*), avec en dessous les dates de début et de fin du morceau suivant. Une interruption créée par le nivellement porte le badge *nivellement*. Une interruption de durée 0 la supprime ; la corbeille par ligne (*Supprimer l'interruption*) la supprime aussi. Effet : la barre est dessinée interrompue et, après *Calculer*, la fin se décale de la durée de l'interruption.
- **Ajouter une interruption** — ajoute une interruption d'une unité de temps au milieu du plus long morceau. Désactivé s'il n'y a pas de place pour une interruption.
- **Supprimer toutes les interruptions** — apparaît quand les interruptions proviennent d'un fichier source sous une forme qui ne peut pas être modifiée ici (*Ces interruptions proviennent du fichier source sous une forme qui ne peut pas être modifiée ici.*). Vous ne voyez alors que les dates.

Voir [Scinder une tâche](docs://howto-taak-splitsen).

## Affectations

- **Affectations** — les ressources de cette tâche. Par ressource : le nom avec une corbeille (*Supprimer*), *Unités/j*, *Travail (rest.)*, *Courbe*, un bouton *Répartition des heures…* et *Déplacer vers…*. En bas se trouve une liste *Affecter une ressource* ; elle affecte la ressource avec 1 unité par jour. Sans ressources, il est écrit *Créez d'abord des ressources (onglet Ressources).* ; quand toutes sont affectées, *Toutes les ressources sont déjà affectées.* Pour un jalon ou une tâche récapitulative, il est écrit que l'affectation n'est pas possible.
- **Unités/j** — quantité de la ressource que la tâche utilise par jour, un nombre supérieur à 0. Effet : la charge dans l'histogramme et la surallocation et, avec une règle de travail, le travail.
- **Travail (rest.)** — travail restant en heures pour cette ressource. Visible uniquement quand les règles de travail sont visibles et que la tâche en a une ; pour le matériel, il y a un tiret. Le cadenas indique quelle grandeur la règle de travail protège (*Protégé par la règle de travail …*). Le triangle d'avertissement (*Diffère de unités × durée*) signifie que le travail enregistré n'est pas égal à unités × durée restante ; l'histogramme suit alors le travail enregistré.
- **Courbe** — la façon dont le travail est réparti sur la durée : *Uniforme*, *Chargé en début*, *Chargé en fin*, *En cloche*, *Pic précoce*, *Pic tardif*, *Double pic* ou *Tortue*. Par défaut : *Uniforme*. Si l'affectation a sa propre répartition des heures, il est écrit *Contour* et la liste est désactivée ; une courbe importée s'appelle *Courbe importée*.
- **Répartition des heures…** — ouvre la répartition des heures par jour ouvré de cette affectation. Voir [Adapter la répartition des heures](docs://howto-urenverdeling-aanpassen).
- **Déplacer vers…** — déplace l'affectation vers une autre tâche terminale qui n'a pas encore cette ressource. Visible uniquement si une telle tâche existe.

## Codes et champs

- **Codes et champs** — visible uniquement si le projet a des codes d'activité ou des champs personnalisés. Chaque code d'activité est une liste avec *(aucun)* et les valeurs sous la forme `code — description` ; par type, vous choisissez au plus une valeur. Chaque champ personnalisé a une zone de saisie adaptée à son type : *Texte*, *Nombre*, *Nombre entier*, *Coût*, *Date* ou *Oui/non*. Effet : aucun effet sur le calcul ; vous pouvez grouper et filtrer par ces champs et les afficher en colonnes. Voir [Codes et champs personnalisés](docs://howto-codes-en-velden).

## Marqueurs sous la règle de travail

Uniquement dans le panneau, et uniquement quand ils s'appliquent.

- **Période non travaillée longue** — *Cette tâche traverse une période non travaillée de … jours (… au …)*, ou avec le nom du jour férié ou de la fermeture de chantier ajouté. S'affiche quand la tâche traverse une suite continue de 8 jours ou plus qui contient au moins un jour férié. C'est un avertissement, pas un refus ; vérifiez si le planning doit être ainsi.
- **Marqueur MS Project** — un badge *Suit la répartition horaire de MS Project*, *La fenêtre de dates MS Project n'est plus appliquée après modification — …* ou *Répartition des heures propre*, avec *En savoir plus*. Il indique si la répartition horaire d'un fichier MS Project détermine encore les dates.
- **Dates enregistrées** — un badge pour un fichier importé avec des dates enregistrées : *Affiche les dates telles qu’enregistrées dans le fichier pour cette tâche* (pour un fichier Primavera *Affiche les dates propres enregistrées par Primavera pour cette tâche*), *Diverge des dates enregistrées* ou *Enregistrement partiellement incomplet — voir les colonnes fin au plus tard/marge*, avec *En savoir plus*. Voir [Dates telles qu’enregistrées](docs://uitleg-datums-zoals-opgeslagen).

## En-tête et pied du panneau

- **Supprimer la tâche** — la corbeille à côté du titre *Tâche* ; supprime cette tâche avec ses sous-tâches, en une seule étape qui s'annule avec *Annuler*. Le planning n'est plus à jour ensuite tant que vous n'appuyez pas sur *Calculer*.
- **Calculer** — le bouton en bas ; même calcul que *Accueil › Planification › Calculer*.

## Ce que vous ne trouvez pas ici

- **Priorité de nivellement** — n'est pas dans la fenêtre ni dans le panneau. Vous la réglez par clic droit et en choisissant *Priorité* (*Basse* = 100, *Normale* = 500, *Haute* = 900) ou en tapant un nombre de 0 à 1000 dans la colonne *Priorité de nivellement*. Par défaut : 500. Effet : le nivellement garde d'abord en place les tâches de priorité plus élevée ; 1000 fige la tâche, de sorte que le nivellement ne la déplace jamais. Voir [Nivellement](docs://uitleg-nivelleren).
- **Autres données de tâche** — le reste de ce qu'une tâche porte, comme les colonnes *Planifiée manuellement*, *Couleur* et les colonnes techniques, se trouve uniquement dans le tableau ; voir [Colonnes du tableau](docs://ref-tabelkolommen).
