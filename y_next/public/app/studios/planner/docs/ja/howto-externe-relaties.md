# 別のプロジェクトへの外部関係

目的は、このプロジェクトのタスクを、別のプロジェクトファイルのタスクにリンクすることです。こうすると、別の場所で計画された作業もスケジュールに反映されます。

## この機能が必要な場合

増築工事は、現場が建築できる状態に整えられてからでなければ開始できません。その作業は請負業者のプロジェクトにあります。または、設置業者は、自分の躯体が完成してからでなければ開始できません。その業者は自分のファイルで計画します。通常の関係は、同じプロジェクト内のタスク同士でのみ機能します。**外部関係** は、タスクを別のファイルのタスクにリンクします。

外部関係は、もう一方のプロジェクトとリアルタイムには計算しません。アプリは固定の **アンカー日付** を保存します。これは、リンクした時点の外部タスクの日付です。計算は、その日付を制限として使います。もう一方のプロジェクトが変わっても、アンカーを更新するまで、自分のプロジェクトでは何も動きません。

## 手順

1. このプロジェクトのタスクを、ちょうど一つだけ選択します。外部タスクに依存するタスク、または外部タスクが依存されるタスクを選びます。
2. *ホーム › タスク › リンク ▾ › 外部関係を追加…* を選択します。同じメニューは *計画 › 関係* と *テーブル › タスク* にもあります。この項目は、タスクが一つだけ選択されている場合にのみ使えます。
3. *外部（プロジェクト間）リンク* ウィンドウで、二つの方法のどちらか一つを選びます。*ソースファイル* を選ぶと、*最近使用したファイルを選択* の下でプロジェクトファイルを選び、次に *ソースタスク* を選びます。アプリはファイルを読み取り専用で読み込みます。ドキュメントとしては開きません。アプリがアンカー日付を自分で引き継ぎます。この方法はデスクトップアプリでのみ動作し、最近使用したファイルの一覧にあるファイルでのみ動作します。それ以外の場合、*ソースファイル* ボタンは無効になります。*手動（フォールバック）* を選ぶと、外部タスクの *プロジェクトID* と *タスクID* を入力します。任意で *タスク名（任意）* を入力し、*アンカー日付* も入力します。ブラウザ版では、この方法だけが使えます。
4. *方向* で、外部タスクが自分の先行タスクか後続タスクかを選びます。選択肢は *先行（外部 → 自分）* と *後続（自分 → 外部）* です。
5. *関係タイプ*（FS、SS、FF または SF）を選びます。必要な場合は *ラグ（稼働日）* を入力します。例として `0d` や `2d` と入力します。
6. *リンクを追加* をクリックし、**計算**（F5）を押します。

手動リンクでアンカーとして入力する日付は、方向と関係タイプによって決まります。

- 外部の**先行タスク**の場合は、関係タイプの最初の文字が重要です。F は外部タスクの終了日、S は開始日を意味します。FS と FF では終了日を、SS と SF では開始日を入力します。
- 外部の**後続タスク**の場合は、関係タイプの二文字目が重要です。S は外部タスクの開始日、F は終了日です。FS と SS では開始日を、FF と SF では終了日を入力します。

時間単位で計画する場合（時間計画がオンで、稼働時間があるカレンダーにタスクがある場合）、*アンカー日付* の欄では、時刻も入力するよう求められます。

例として、現場プロジェクトのプロジェクト終了日は2027年6月18日（金曜日）です。*Groundwork* を、関係タイプ FS の外部先行タスクとしてリンクします。アンカー日付は2027年6月18日です。**計算** のあと、*Groundwork* は6月21日（月曜日）に開始します。これは、アンカー日付の後の最初の稼働日です。外部の後続タスクは逆向きに作用します。自分のタスクをいつまでに終了させてよいかを制限します。

## 表示内容と管理方法

- 外部関係は、タスクテーブルの *先行タスク* 列と *後続タスク* 列に文字として表示されます（テーブルの見出しにある **+** から、*関係* の下で追加します）。表示には、プロジェクトとタスクの名前、そして関係タイプが含まれます。*ソースがありません* と表示された小さな三角は、ソースがまだ読み込まれていないことを示します。リンクにマウスポインターを合わせると、プロジェクト、タスクID、アンカー日付、ソースの状態を確認できます。プロジェクト名は、分かった時点で *プロジェクトID* の行に表示されます。
- Gantt 図では、タスクの位置に灰色のゴーストバーが表示されます。先行タスクの場合、バーはアンカー日付で終わります。後続タスクの場合、バーはアンカー日付で始まります。赤い *古い* のラベルが付いた破線の枠は、ソースがまだ読み込まれていないことを示します。手動リンクでは、これが常にあてはまります。
- 列にあるリンクを右クリックすると、メニューに *外部関係を編集…* と *依存関係を削除* が表示されます。リンクにソースファイルがある場合は、*ソースを更新* も表示されます。
- *リンク ▾ › すべての外部関係を更新* を選ぶと、ソースファイルを再度読み込み、アンカーを更新します。これはデスクトップアプリでのみ動作します。手動リンクしかない場合、アプリは *更新可能な外部ソースがありません（ファイルパスがありません）。* と表示します。更新のあとに **計算** を押します。
- 関係タイプや方向を変えると、アンカーは外部タスクの別の側を使う必要が出る場合があります（終了日の代わりに開始日、またはその逆）。手動リンクでは、アプリは次のメッセージを表示して新しいアンカーを求めます。*新しいアンカーを選択してください。関係タイプはソースタスクの反対側を使用するようになりました。* ソースファイルがあるリンクでは、アプリがアンカーを自分で再度読み込みます。

## 注意点とアプリの動作

**もう一方のプロジェクトは追従しません。** 外部タスクの日付が変わると、更新するかアンカーを変えるまで、スケジュールは古いアンカーで計算を続けます。手動の方法では、リンクを右クリックして *外部関係を編集…* を選び、アンカー日付を自分で変更します。

**外部の先行タスクは下限です。** 自分のタスクが、自分の先行タスクのために、アンカーが求めるより遅く開始する場合は、その関係が優先されます。アンカーは、後ろへ押すだけです。

**外部の後続タスクは上限です。** アンカーが厳しすぎる場合、自分のタスクとその前にあるタスクに負のフロートとして表示されます。これには別の警告は表示されません。そのため、*トータルフロート* 列を確認してください。

**固定ラグのみ。** 外部関係では、暦日やパーセントでラグを指定できません。アプリは *外部関係は稼働日または稼働時間による固定ラグのみ対応しています。* と表示します。稼働日は、自分のタスクのカレンダーで数えます。時間単位のラグは、時間計画のタスクでのみ有効です。日単位のタスクでは、計算はそれを無視します。その場合は稼働日を使ってください。

**別のファイルのプロジェクトID。** プロジェクトIDは欄や列にはありません。そのプロジェクトの IFC に `InternalProjectId` として保存されています。プロジェクトを開き、*IFC* タブに進んで、*IFC を生成* を選択します。計算に使われるのはアンカー日付だけです。ただし、プロジェクトIDは単なるラベルではありません。更新のとき、アプリはまずプロジェクトIDでソースファイルを認識します（次にファイルパスで認識します）。手動リンクに、ソースファイルのものと同じプロジェクトIDを入力すると、そのファイルを更新するときにリンクも一緒に更新されます。別のプロジェクトのタスクの *タスク ID* は、そのプロジェクトのテーブルで見つかります。*技術情報* の下にある *タスク ID* 列です。
