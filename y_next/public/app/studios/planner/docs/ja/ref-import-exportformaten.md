# インポートとエクスポートの形式

ファイル形式ごとに、開けるか、保存できるか、エクスポートできるかを示します。また、何が引き継がれて何が引き継がれないか、どの計算プロファイルで開くかも示します。この仕組みの理由と、数字を使った例は [ファイルと形式](docs://uitleg-bestanden) にあります。

## 概要

**開く** は IFC、CSV、MS Project XML、Primavera P6 XML、`.mpp`、`.xer` で可能です。ファイル名の末尾が上記以外のファイルは、アプリが IFC として扱います。

**保存** は常に IFC 形式で書き込みます。開いた IFC ファイルだけが保存先になります。他の形式のプロジェクトは、開いた後にファイルがありません。その場合は *保存* を選ぶと、IFC ファイルの保存先を尋ねられます。

**エクスポート** は IFC 4x3、MS Project XML、Primavera P6 XML、CSV、進捗シート（Excel と CSV）に対応しています。エクスポートはプロジェクトを変更しません。

**読み取り専用** は `.mpp` と `.xer` です。アプリはこれらを開けますが、書き込めません。

**PDF** は、レポートからのみ出力されます（[レポートの種類](docs://ref-rapporttypes) を参照）。アプリは PDF を読み込みません。

**場所。** 開くには *ホーム › ファイル › 開く*、*ファイル › 開く*、または Ctrl+O を使います。エクスポートするには *ホーム › ファイル › エクスポート* または *ファイル › エクスポート* を使います。記入済みの進捗シートは *ファイル › インポート* から読み込むか、*計画*、*テーブル*、*レポート* タブのリボングループ *進捗* にあるボタン *シートから進捗を更新* を使います。

**開くときの計算プロファイル。** どの形式も計算プロファイルを持って開きます。その内容は [計算オプションと規則](docs://ref-rekenopties-en-conventies) にあります。`.xer` は *Primavera P6* で、`.mpp` は *Microsoft Project* で開きます。CSV、MS Project XML、P6 XML は *Open Planner Studio* で開きます。IFC は、ファイルに保存された計算プロファイルを使います。`.xer` と `.mpp` では、アプリがプロジェクトをこの方法で計算することを示します。計算プロファイルと計算オプションを保持するのは IFC だけです。計算オプションのうち、MS Project XML が書き込むのは最大でクリティカルのしきい値までです。他の形式のエクスポートを開き直すと、*Open Planner Studio* として計算されます。

## IFC

**開く** — はい、`.ifc` を開けます。アプリは IFC 4.3 を読み込みます。計算プロファイル: ファイルに保存されているもの。

**保存** — はい。IFC は保存できる唯一の形式です。*保存* を選ぶと、プロジェクト全体が IFC ファイルとして保存されます。そのファイルが保存先になります。

**エクスポート** — はい。*IFC 4x3* として（説明文: *BuildingSMART 標準。BIM モデルとの 4D 連携。*）。既定の名前は、プロジェクト名に `.ifc` を付けたものです。プロジェクトがリソースライブラリに関連付けられている場合、チェックボックス *ライブラリファイルも一緒に保存* は *ファイル › エクスポート* のカードの下にあります。オンにすると、アプリはプロジェクトの後に *projectname-bibliotheek.ifc* の保存先を尋ねます。このチェックボックスは *ホーム* タブの一覧にはありません。

**引き継がれるもの** — プロジェクトに属するすべてです。構造を持つタスク、期間、日付、進捗。ラグ付きの関係。制約と期限。カレンダー。リソースと割り当て（時間配分を含む）。ベースライン。アクティビティコードとカスタムフィールド。メモ。他のプロジェクトへの外部関係。中断。作業ルールとタスク種類。状態日、進捗モード、計算プロファイル、計算オプションなどのプロジェクト設定。リソースライブラリとの関連。`.xer` から開いたプロジェクトでは、元のソースファイルも一緒に引き継がれます。カスタムのタスク種類は、IFC の型 `USERDEFINED` として保存され、名前は ObjectType フィールドに入ります。そのため、他の IFC プログラムでもタスクを通常どおり読めます。アプリは型の固定 ID も保持するので、名前を変えてもリンクは壊れません。別のコンピューターでファイルを開くと、その種類は *このプロジェクトから* の下に表示され、相手側の *自分のタスク種類* には表示されません。

**引き継がれないもの** — 画面の設定（ズーム、スクロール位置、選択中のタスク、折りたたんだフェーズ、選んだフィルターとグループ化）と、アプリの設定（[設定](docs://ref-instellingen)）です。*IFC* タブには、プロジェクトの IFC テキストが表示されます。

## MS Project XML (MSPDI)

**開く** — はい。アプリは、MS Project の名前空間（または名前空間なし）のルート要素 `Project` を持つ `.xml` ファイルを MS Project XML として認識します。計算プロファイル: *Open Planner Studio*。

**保存** — いいえ。このようなプロジェクトには保存先がありません。

**エクスポート** — はい。*MS Project XML* として（説明文: *Microsoft Project で開けます。完全な WBS 構造。*）。既定の名前は、プロジェクト名に `.xml` を付けたものです。

**引き継がれるもの** — 構造（階層と WBS）、期間、日付、進捗を持つタスク。時間またはパーセンテージのラグを含む関係。期限を含む制約。タスクとリソースのカレンダーを含むカレンダー。曲線または時間配分を含むリソースと割り当て。状態日。クリティカルのしきい値は、0 以上の整数の稼働日数として、*トータルフロート ≤ しきい値* と書き込まれます。タスクの説明（メモとして）。タスクの作業ルール（MS Project のタスク種類として）。カスタムのタスク種類は、アプリが読み戻す自由なフィールド（`ExtendedAttribute`）に入ります。MS Project はこれを無視する場合があります。ベースラインのうち有効なものだけが、ベースライン 0 として引き継がれます。時間を単位とするタスクは、その単位を保持します。マイルストーンは、その種類（開始、終了、または自動）を保持します。

**引き継がれないもの** — メモ（タスクのチェックリスト）、他のプロジェクトへの外部関係、アクティビティコードとカスタムフィールド、二つ目の制約、*手動スケジュール* の印、山崩し遅延、順序外タスクの再開点と停止点、MS Project プロファイルの規則 *残作業は経過期間の後に再開* と *未開始タスクをステータス日付へ移動しない*、そのほかの計算オプションです。時間配分のない中断タスクは、中断を除いて引き継がれます。

**変わるもの** — *必須（ピン留めロジック）* を選ばない *指定日に開始 (MSO)* または *指定日に終了 (MFO)* の制約は、*指定日以降に開始 (SNET)* または *指定日以降に終了 (FNET)* になります。ハンモックは、計算された日付を持つ通常のタスクになります。

## MS Project ファイル (`.mpp`)

**開く** — はい。MS Project 2010 から 2021 までのファイルを開けます。計算プロファイル: *Microsoft Project*。アプリはファイルを読むだけで、`.mpp` を変更することはありません。MS Project 2007 以前のファイルと、パスワード付きのファイルは開けません。その場合は、MS Project の XML エクスポートを案内するメッセージが表示されます。

**保存** — いいえ。保存先はありません。*保存* を選ぶと、新しい IFC ファイルが書き込まれます。

**エクスポート** — いいえ。

**引き継がれるもの** — 構造、期間、制約を持つタスク。ラグ付きの関係。カレンダー。リソースと割り当て。進捗。MS Project で自分で入力した WBS コード。MS Project が自分で計算した日付とフロートも読み込まれます。これは表示 *記録されたとおりの日付* で使われます。

**引き継がれないもの** — ベースライン、コストと単価、メモ、MS Project のカスタムフィールド。詳しくは [MS Project ファイル (.mpp) を開く](docs://howto-mpp-openen) を参照してください。

**由来とライセンス** — `.mpp` の読み込み機能は Open Planner Studio のために作られました。MPXJ（`github.com/joniles/mpxj`、Jon Iles ほか）のソースコードと構造に関する知識から派生しています。MPXJ は LGPL-2.1 の Java ライブラリです。構造とフィールドの定数は TypeScript に移植されました。Open Planner Studio 自体は LGPL-3.0 のオープンソースです。`.xer` の読み込み機能は派生物ではありません。そこでは、MPXJ は理解の参考としてのみ参照されました。

## Primavera P6 XML

**開く** — はい。アプリは、ルート要素 `APIBusinessObjects` を持つ `.xml` ファイルを P6 XML として認識します。計算プロファイル: *Open Planner Studio*。

**保存** — いいえ。

**エクスポート** — はい。*Primavera P6 XML* として（説明文: *Oracle Primavera P6 用。*）。既定の名前は、プロジェクト名に `.xml` を付けたものです。そのため、MS Project XML のエクスポートと同じ名前になります。名前は自分で別々に付けてください。

**引き継がれるもの** — WBS 構造と、期間、日付、進捗を持つタスク。ラグ付きの関係。制約（二つ目も、ソフト制約として）。カレンダー。リソースと割り当て。状態日（`DataDate` として）。カスタムのタスク種類は、専用のフィールド `OPS Custom Task Type` に入ります。アプリはこれを読み戻しますが、P6 は無視する場合があります。

**引き継がれないもの** — ベースラインと期限。アクティビティコード、カスタムフィールド、メモ、外部関係。計算オプション。P6 にはパーセンテージのラグがないため、アプリはそれを固定の日数に変換します。暦日のラグは稼働時間のラグになります。例えば、3 暦日は 3 稼働日になります。ハンモックは通常のタスクになり、手動スケジュールのタスクは計算された日付を持つ通常のタスクになります。一日未満の山崩し遅延は削除されます。

## Primavera ファイル (`.xer`)

**開く** — はい。計算プロファイル: *Primavera P6*。アプリはファイルを読むだけです。`.xer` を書き込むことはなく、ファイルを変更することもありません。タスクを持つプロジェクトごとに 1 つのタブを開きます。アクティビティがない、または破損したテーブルを持つファイルは、メッセージとともに開けません。

**保存** — いいえ。保存先はありません。*保存* を選ぶと、元の `.xer` を中に入れた新しい IFC ファイルが書き込まれます。

**エクスポート** — いいえ。`.xer` から開いたプロジェクトを CSV、MS Project XML、P6 XML にエクスポートすると、アプリは XER のソース情報が失われると通知します。途中で IFC として保存していても、この通知は表示されます。IFC では何も失われません。

**引き継がれるもの** — WBS 構造と、期間、日付、制約、進捗を持つアクティビティ。ラグ付きの関係。カレンダー。割り当てを持つリソース。アクティビティコード。カスタムフィールド（UDF）。メモ。P6 のスケジュール設定。アクティビティの種類 *Level of Effort* はハンモックになります。ベースラインのプロジェクトは、それを参照するプロジェクトの有効なベースラインになります。二つのプロジェクト間の関係は、アプリがソースデータとして保持します。

**引き継がれないもの** — アクティビティのないプロジェクト、および、スケジュール内の実際の関係としての二つのプロジェクト間の関係。詳しくは [Primavera P6 ファイル (.xer) を開く](docs://howto-xer-openen) を参照してください。

## CSV

**開く** — はい。アプリは `;` と `,` を区切り文字として読みます。列見出しは英語とオランダ語で認識します（例: `Name` または `Naam`、`Duration` または `Duur`、`Predecessors` または `Voorgangers`）。日付は *年-月-日*、*日-月-年*、または *日/月/年* の形式にできます。先行タスクは、WBS コード、関係の種類、ラグの順に書きます（例: `1.2FS+2d`）。計算プロファイル: *Open Planner Studio*。プロジェクト名は *CSV Import* になります。固定コード以外の `Task Type`（例: `CONSTRUCTION` や `INSTALLATION`。アプリ自身が書き込みます）は、*このプロジェクトから* の下にカスタムのタスク種類になり、*自分のタスク種類* には入りません。`OPS Custom Task Type ID` があると、カスタム種類の ID が保持されます。

**保存** — いいえ。

**エクスポート** — はい。*CSV (;)* として（説明文: *汎用テーブルエクスポート。日付と期間を含むすべてのタスク。*）、カード *CSV（セミコロン区切り）* にあります。ファイルは区切り文字にセミコロンを使い、UTF-8（BOM 付き）で、列見出しは英語です。

**引き継がれるもの** — タスクごとに次の列があります：`OPS Task ID`、`WBS`、`Outline Level`、`Name`、`Duration (days)`、`Start`、`Finish`、`Predecessors`、`Task Type`、`OPS Custom Task Type ID`、`Status`、`Completion (%)`、`Actual Start`、`Actual Finish`、`Critical`、`Total Float`、`Description`。完了率は整数のパーセントで書かれます。

**引き継がれないもの** — リソース、割り当て、カレンダー、制約、期限、ベースライン、状態日。日付が表示 *記録されたとおりの日付* にある場合、エクスポートは、ソースファイルが記録していなかったタスクの `Critical` と `Total Float` を空のままにします。

## 進捗シート（Excel と CSV）

**開く** — はい。*ファイル › インポート*（*シートから進捗を更新*）から開くか、*計画*、*テーブル*、*レポート* の各タブのリボングループ *進捗* にある同じ名前のボタンから開きます。アプリは `.xlsx` と `.csv` を読み込みます。上限は 16 MB と 50,000 行です。これはプロジェクトを開くものではありません。開いているプロジェクトの進捗を更新します。詳しくは [シートから進捗をインポートする](docs://howto-voortgang-importeren) を参照してください。

**保存** — いいえ。

**エクスポート** — はい。*進捗シート（Excel）*（リストでは *進捗（Excel）*）と *進捗シート（CSV）*（*進捗（CSV）*）として。既定の名前は *projectname-voortgang* です。同じリボングループのボタン *進捗シートをエクスポート* を使うと、ワンクリックで Excel シートを作成します。Excel シートには、固定の列幅、ロックされたフィールド、日付チェックがあります。CSV シートは、同じ内容をプレーンテキストで持ちます。

**引き継がれるもの** — 列 `OPS Task ID`、`WBS`、`Name`、`Start`、`Finish`、`Completion (%)`、`Actual Start`、`Actual Finish`。読み込み時、アプリは `Completion (%)`、`Actual Start`、`Actual Finish` を使います。`Start` と `Finish` は日付の表記を認識するためだけに使われ、スケジュールは変わりません。アプリは行を `OPS Task ID` で、または一意の WBS コードでタスクに関連付けます。

**引き継がれないもの** — これらの列以外のすべてです。期間、関係、リソース、スケジュールのその他の部分。サマリータスクは、シートから進捗を受け取りません。

## PDF

**開く** — いいえ。

**保存** — いいえ。

**エクスポート** — はい。レポートから出力します。*レポート* タブのボタン *PDF エクスポート* を使います。アプリは、レポートをプリンターへ直接送りません。紙に出すには PDF を使います。内容はレポートの種類によって決まります。[レポートの種類](docs://ref-rapporttypes) と [レポートを作成して印刷する](docs://howto-rapport-maken-en-afdrukken) を参照してください。
