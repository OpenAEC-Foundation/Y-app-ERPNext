# 制約と期限

レンガは6月21日にしか納品されません。許可証はまだ届いていません。屋根は建設業休暇の前に閉じておく必要があります。関係は、タスクが別のタスクを待つことを記録します。しかし、日付の取り決めは作業の順序からは決まりません。そのために制約と期限があります。この記事では、各種類の働き、タスクが移動する場合とフロートだけが変わる場合、ハードピンの意味、およびアプリが競合を報告する方法を説明します。

これらの規則と例は、計算プロファイル *Open Planner Studio* を使い、月曜日から金曜日までを作業週とする新しいプロジェクトに適用されます。

## 概念

**制約** は、1 つのタスクに対する日付の制限です。関係とは無関係に働きます。この制限は 2 通りに働きます:

- **押し出す**: タスクは、その日付より前に開始することも終了することもできません。関係により、タスクがその日付より前に開始する場合、タスクは日付まで移動します。
- **守る**: タスクは、遅くとも日付までに開始または終了する必要があります。アプリはタスクを移動しません。スケジュールがその日付を満たさない場合、タスクとその前の連鎖の **フロート** は負になります。フロートとは、プロジェクトの終了日が動く前にタスクが持つ余裕です。負とは、計算上はすでに遅れていることを意味します（[クリティカルパスとフロート](docs://uitleg-kritiek-pad) を参照）。

**期限** は、守ることをより簡単にした形です。タスクの終了に対する目標日ですが、タスクは何によっても移動されません。

すべての制約は **ソフト** です。日付を満たせなくても、計算は続きます。例外は 1 つだけです。**ハードピン** は関係より優先されます。これについては後で詳しく説明します。

## アプリの計算方法

### 8 種類

*プロパティ* パネルの *制約* で種類を選びます。各種類の計算方法は次のとおりです:

- *できるだけ早く (ASAP)*: 制限はありません。これが既定値です。タスクは、関係が許す限り早く開始します。
- *できるだけ遅く (ALAP)*: タスクは、後続タスクの開始を遅らせずに済む限り遅く移動します。そのため、フリーフロートを使い切ります。後続タスクにそれ自身の余裕があるため、その後もトータルフロートが残る場合、タスクは非クリティカルのままです。そのトータルフロートも使い切る場合、タスクはクリティカルと数えられます。
- *指定日以降に開始 (SNET)*: 開始の下限です。タスクがそれより前に開始する場合、タスクは日付まで移動します。日付が関係の許す時点より前の場合、制約は何もしません。
- *指定日以降に終了 (FNET)*: 同じですが、タスクの終了に対するものです。
- *指定日以前に開始 (SNLT)* および *指定日以前に終了 (FNLT)*: 開始または終了の上限です。どちらも何も移動しません。上限を満たさない場合、アプリは制約違反を報告し、フロートは負になります。
- *指定日に開始 (MSO)* および *指定日に終了 (MFO)*: 下限と上限を同時に設定します。日付が関係の要求より遅い場合、タスクは日付まで移動します。日付が関係の許す時点より前の場合、タスクは関係が置いた位置にとどまり、フロートは負になります。

日付が土曜日、日曜日、または非稼働日に当たる場合、アプリはそれを稼働日として扱います。下限（SNET、FNET）は次の稼働日として、上限（SNLT、FNLT）は前の稼働日として扱います。

### 負のフロートの意味

上限は逆向きに働きます。制約がタスクの遅い日付を早い日付より前に置く場合、トータルフロートは負になります。その前のタスクにも同じことが当てはまります。たとえば、*Brickwork* は遅くとも6月11日（金曜日）までに開始する必要があり、6月14日（月曜日）より前には開始できない場合、*Brickwork* の前のタスクも 1 稼働日遅れます。負のフロートを持つすべてのタスクはクリティカルです。その仕組みは [クリティカルパスとフロート](docs://uitleg-kritiek-pad) で説明しています。

上限が原因でバーが移動することはありません。競合は、負の *トータルフロート*、バーの上の赤いひし形、*ステータスバー* の通知（例: *制約違反: 1 件*）、および *警告* パネルで確認できます。

### ハードピン

MSO と MFO では、チェックボックス *必須（ピン留めロジック）* が表示されます。このチェックを入れると、先行タスクがその時点までに終わっていなくても、タスクを日付に固定します。関係は上書きされます:

- タスクは日付に置かれます（MSO の場合はその日に開始し、MFO の場合はその日に終了します）。また、先行タスクと重なります。
- 先行タスクは負のフロートになります。また、関係によってタスクがピンよりも遅く開始できる場合、アプリは制約違反を報告します。ピン留めされたタスク自体は、フロートが 0 のままです。
- 後続タスクは、ピン留めされたタスクから計算されます。そのため、その前のロジックが終わっていなくても、ピンがない場合より早く開始できます。下の例では、このためプロジェクトの終了が 3 稼働日前倒しされます。

ピンを初めてオンにすると、アプリは短い説明を表示します。ハードピンは関係を上書きし、先行タスクより前であっても、バーは日付に固定される、という内容です。

### 副制約

タスクには 1 つの主制約があります。2 つ目の制限も設定したい場合、たとえば、6月14日より前に開始できず、6月17日までに終了しなければならないタスクの場合は、**副制約** を追加します。副制約は実際の制限（SNET、FNET、SNLT または FNLT）である必要があり、主制約とは反対方向に制限する必要があります。つまり、下限（SNET または FNET）には上限（SNLT または FNLT）を組み合わせます。SNET と SNLT の組み合わせは許可されますが、SNET と FNET は許可されません。アプリは、その他の組み合わせを赤で表示し、理由を示します。例: *主制約と副制約は同じ側を境界にできません。* ASAP、ALAP、MSO、MFO、およびハードピンの場合、副制約は許可されません。

### 期限

期限は、制約とは別に、タスク上に設定する独立した日付です。終了の上限です。何も移動しませんが、タスクが期限内に終わらない場合、フロートは負になります。アプリは、その後 *警告* パネルに *期限 … を超過 — 最早終了 …* と報告し、ステータスバーには超過した期限の数が表示されます。Gantt では、期限の日付に下向きの矢印が表示されます。タスクが期限内に終わっている間は緑、遅れるとすぐに赤になります。土曜日の期限は、その前の金曜日まで（金曜日を含む）として数えます。

フロートについては、期限は FNLT と同じ働きをします。違いは使い方にあります。期限は守りたい目標日です。制約とは別に扱われるため、タスクは制約と期限の両方を持てます。FNLT は制約です。違反は、超過した期限ではなく、制約違反として表示されます。

### 制約ができないこと

- **フェーズ**（サマリータスク）の制約または期限は数えられません。アプリはフェーズ内のタスクで計算します。制約や期限は、そのタスク自体に設定してください。
- すでに実績開始日または進捗があるタスクは、その開始日を保ちます。後の日付を指定した SNET でも、タスクは移動しません。
- 先行タスクがあるタスクに **開始日を入力する** と、固定の開始にはなりません。先行タスクが引き続き決めます。そのため、アプリは入力した日付の SNET に変換します。これは *プロパティ* パネル、*タスクの編集*、テーブル、または Gantt でバーを動かしたときに行われます。アプリはその旨を通知します。タスクがすでに別の制約（例: ALAP や MSO）を持つ場合、アプリは新しい開始日を適用せず、その旨も通知します。その場合は、その制約を変更してください。

すべての変更は **計算**（F5）の後にのみ表示されます。

## 計算例

この例は、住宅の増築のための小さなタスクのネットワークです。2027年6月7日（月曜日）に開始します:

- *Groundwork*（3 稼働日）: 6月7日（月曜日）から6月9日（水曜日）まで。
- *Pour foundation*（2）: 6月10日（木曜日）と6月11日（金曜日）。
- *Brickwork*（5）: 6月14日（月曜日）から6月18日（金曜日）まで。
- *Roofing*（3）: 6月21日（月曜日）から6月23日（水曜日）まで。
- *Scaffolding*（2）: *Pour foundation* の後に続き、*Roofing* の前に来ます。6月14日（月曜日）と6月15日（火曜日）に実行され、3 稼働日のフロートがあります。

クリティカルパスは *Groundwork*、*Pour foundation*、*Brickwork*、*Roofing* です。プロジェクトは6月23日（水曜日）に完了します。*Brickwork* に 1 つの制約を設定すると、何が変わるでしょうか？

- **SNET 6月21日（月曜日）**（レンガは、その日にしか届きません）: *Brickwork* は6月21日（月曜日）から6月25日（金曜日）まで実行され、*Roofing* は6月28日（月曜日）から6月30日（水曜日）まで実行されます。プロジェクトは6月30日（水曜日）に完了します。*Groundwork* と *Pour foundation* は 5 稼働日のフロートを持つようになり、もうクリティカルではありません。*Scaffolding* は 8 稼働日のフロートを持ちます。
- **SNET 6月9日（水曜日）**: 効果はありません。関係上、*Brickwork* は、いずれにしても6月14日（月曜日）にしか開始できません。
- **SNLT 6月16日（水曜日）**: 効果はありません。*Brickwork* は6月14日（月曜日）に開始し、上限には十分余裕を持って間に合います。
- **SNLT 6月11日（金曜日）**: 余裕が足りません。*Brickwork* は、それでも6月14日（月曜日）に開始し、1 稼働日遅れます。*Groundwork*、*Pour foundation*、*Brickwork* は −1 稼働日のフロートになり、アプリは *制約 指定日以前に開始 (SNLT) 11-06-2027 がロジックによって上書きされています（負のフロート）* と報告します。何も移動しません。
- **MSO 6月16日（水曜日）**（ハードピンなし）: *Brickwork* は6月16日（水曜日）に移動し、6月22日（火曜日）に完了します。*Roofing* は6月23日（水曜日）から6月25日（金曜日）まで実行され、プロジェクトは6月25日（金曜日）に完了します。
- **MSO 6月11日（金曜日）**（ハードピンなし）: 日付は、関係が許す時点より前です。*Brickwork* は、それでも6月14日（月曜日）に開始し、フロートは −1 になります。SNLT の場合と同じです。
- **MSO 6月9日（水曜日）、ハードピンあり**: *Brickwork* は6月9日（水曜日）に開始し、6月15日（火曜日）に完了します。一方、*Pour foundation* は6月11日（金曜日）まで実行されます。*Roofing* は6月16日（水曜日）から6月18日（金曜日）まで実行されます。プロジェクトは、ピンがない場合より 3 稼働日早く完了します。*Groundwork* と *Pour foundation* は −3 稼働日のフロートになります。

さらに、別のタスクに制約または期限を設定した場合:

- **ALAP** を *Scaffolding* に設定: タスクは6月17日（木曜日）と6月18日（金曜日）に移動します。これは *Roofing* の前の最も遅い時点です。*Roofing* はその唯一の後続タスクで、ちょうど 3 稼働日のフロートの余裕がありました。その余裕は今使い切られ、*Scaffolding* はクリティカルになります。
- **SNET 6月19日（土曜日）** を *Scaffolding* に設定: 制限は6月21日（月曜日）として数えられます。*Scaffolding* は6月21日（月曜日）と6月22日（火曜日）に実行され、*Roofing* もそれに合わせて6月23日（水曜日）から6月25日（金曜日）まで移動します。
- **期限 6月18日（金曜日）** を *Roofing* に設定: 何も移動しません。*Roofing* は6月21日（月曜日）から6月23日（水曜日）のままです。*Groundwork*、*Pour foundation*、*Brickwork*、*Roofing* は −3 稼働日のフロートになり、アプリは *期限 18-06-2027 を超過 — 最早終了 23-06-2027* と報告します。*Scaffolding* は 0 稼働日のフロートのままで、こちらもクリティカルになります。
- **SNET 6月21日（月曜日）** を *Brickwork* に、**期限 6月25日（金曜日）** を *Roofing* に設定: 制約により、*Brickwork* が 1 週間後ろに押し出され、期限により *Roofing* が6月30日（水曜日）に遅れることが報告されます。*Brickwork* と *Roofing* は −3 稼働日のフロートになります。*Groundwork* と *Pour foundation* は 2 稼働日のままです。

チュートリアル 3 では、チュートリアルプロジェクトで自分で制約と期限を設定し、スケジュールがどのように動くかを確認します。

## 影響と誤解

**「制約はタスクを移動させる。」** 関係より後ろにタスクを置けるのは SNET、FNET、MSO、MFO だけです。ALAP は、フリーフロートの範囲内でタスクを後ろに移動させられます。SNLT と FNLT は何も移動させません。警告するだけです。その場合に日付を守るには、その前の連鎖を短くする必要があります。

**「負のフロートはアプリの不具合です。」** これは、スケジュールが日付の取り決めと競合していることを示すシグナルです。連鎖を短くするか、取り決めを緩めるか、競合を意図的に受け入れることで解決します。

**「ハードピンは競合を解決する。」** ハードピンは競合を隠します。タスクは日付に置かれますが、先行タスクはその準備ができておらず、後続タスクはそれらが準備できているかのように計算されます。ハードピンは、法的な引き渡し日のように本当に固定されている日付にだけ使ってください。タスクを日付に置くための手段としては使わないでください。

**「開始日を入力するだけだ。」** 先行タスクがあるタスクでは、それは SNET になります。その日付が先行タスクの許す時点より前の場合、何もしません。

**「期限か FNLT か？」** 守りたい目標日には期限を選び、スケジュールの境界条件となる日付には制約を選んでください。

**「フェーズに制約を設定する。」** それは数えられません。制約はタスク自体に設定してください。
