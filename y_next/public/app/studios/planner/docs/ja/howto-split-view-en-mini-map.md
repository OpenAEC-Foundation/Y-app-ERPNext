# 分割ビューとミニマップの使い方

目標: タイムラインの二つの区間を並べて表示し、長いスケジュールをすばやく移動することです。

## この機能が必要な場合

基礎工事の開始と、九か月後の引き渡しについて、同時に話し合っています。この機能がなければ、ズームインとズームアウトを繰り返し、どこを見ていたかわからなくなります。**分割ビュー** を使うと、同じスケジュールが二つ並んで表示されます。それぞれが独自の時間ウィンドウを持ちます。**ミニマップ** を使うと、プロジェクト全体の期間が一本の細い帯で表示されます。探している部分をクリックすると、そこへ移動できます。

## 手順

### 分割ビューをオンにする

1. *表示* タブを選択します。*プレゼンテーション* グループには、*プレゼンテーション*、*分割ビュー*、*ミニマップ* があります。
2. *分割ビュー* をクリックします。Gantt が二つに分かれます。どちらのウィンドウも、現在のビューのズームと位置で始まります。

二つのウィンドウは、タスクテーブル、行、縦方向のスクロールを共有します。各ウィンドウが個別に持つのは時間軸です。具体的には、ズームと横方向の位置です。

### 各ウィンドウに個別の時間範囲を設定する

- マウスがあるウィンドウで、ズームとスクロールをします。*スクロールとズーム* の既定の設定（*ズーム＋ドラッグ*）では、マウスホイールでそのウィンドウをマウスの位置を中心にズームします。別のモードに設定している場合は、ホイールは両方のウィンドウで、そのモードが定める動作をします。
- 既定の設定では、Shift キーを押しながらマウスホイールで行をスクロールします。これは両方のウィンドウに同時に適用されます。
- *ズーム＋* と *ズーム－* のボタン、およびタイムスケールのリスト（例: *四半期*）は、左のウィンドウだけに働きます。そのため、右のウィンドウのズームはマウスホイールで行います。
- 二つのウィンドウの間の仕切りを左右にドラッグすると、ウィンドウの幅を広くしたり狭くしたりできます。初期状態では、各ウィンドウが半分ずつの幅です。

### 分割ビューをオフにする

もう一度 *分割ビュー* を選択します。左のウィンドウのビューで、ウィンドウが一つ残ります。次に分割ビューをオンにすると、その時点のビューで新しく始まります。

### ミニマップをオンにする

1. *プレゼンテーション* グループで、*ミニマップ* をクリックします。
2. タイムラインの下に、プロジェクト全体の期間を示す帯が表示されます。帯には、現在のビューのタスクが細い線として表示されます。フィルターを使っている場合は、そのフィルターで表示されるタスクだけが表示されます。また、今見ている部分を囲む枠も表示されます。
3. 帯の任意の場所をクリックすると、枠がそこへ移動します。ウィンドウはその場所を中心に表示されます。または、枠をつかんでドラッグします。

ミニマップが動かすのは時間ウィンドウだけです。行はそのままです。

分割ビューがオンの場合、各ウィンドウは、タイムラインのそれぞれの部分の下に、独自の帯を持ちます。各帯は、その上にあるウィンドウだけを操作します。

## 注意点とアプリの動作

**ミニマップは、プロジェクト全体がすでに表示されている場合は何もしません。** スケジュール全体が収まるまでズームアウトすると、移動先がないため、クリックしても効果がありません。先にズームインしてください。

**ミニマップは Gantt だけにあります。** *テーブル*、*IFC*、*レポート* タブと、リソースパネル全体（*リソース*。*リソースドック* ではない）には、タイムラインがありません。そのため、ミニマップも分割ビューもありません。Gantt のあるビューに戻ると、再び表示されます。

**分割ビューはプロジェクトに属しますが、ミニマップは属しません。** 分割ビューは開いているプロジェクトに適用されます。別のプロジェクトに切り替えてから戻っても、分割ビューは残ります。ミニマップはすべてのプロジェクトで共通の一つの設定で、アプリを再起動してもオンまたはオフのまま残ります。どちらも画面の設定です。プロジェクトファイルには保存されず、プロジェクトを「変更済み」にもせず、*元に戻す* の対象にもなりません。

**分割ビューとプレゼンテーション。** どちらも、プレゼンテーションモードに切り替えても表示されたままです（[大きな画面でのプレゼンテーション](docs://howto-presentatie) を参照）。このモードではリボンが消えるため、もうオンやオフにはできません。そのため、開始する前に正しく設定してください。
