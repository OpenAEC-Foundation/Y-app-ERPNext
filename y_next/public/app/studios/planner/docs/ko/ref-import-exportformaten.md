# 가져오기 및 내보내기 형식

파일 형식별로 설명합니다. 파일을 열거나, 저장하거나, 내보낼 수 있는지 확인하세요. 무엇이 함께 넘어가고 무엇이 넘어가지 않는지도 설명합니다. 또한 파일을 열 때 쓰는 계산 프로필도 설명합니다. 이 모든 이유와 숫자 예시는 [파일과 형식](docs://uitleg-bestanden)에 있습니다.

## 한눈에 보기

**열기**는 IFC, CSV, MS Project XML, Primavera P6 XML, `.mpp`, `.xer` 형식을 지원합니다. 다른 확장자의 파일은 앱이 IFC로 처리합니다.

**저장**은 항상 IFC 파일로 씁니다. 열린 IFC 파일만 저장 대상이 됩니다. 다른 형식에서 연 프로젝트에는 열린 뒤 파일이 없습니다. 그런 경우 *저장*을 누르면 앱이 IFC 파일을 어디에 저장할지 묻습니다.

**내보내기**는 IFC 4x3, MS Project XML, Primavera P6 XML, CSV, 진행률 시트 두 가지(Excel과 CSV)로 가능합니다. 내보내도 프로젝트는 바뀌지 않습니다.

**읽기 전용**은 `.mpp`와 `.xer` 파일입니다. 앱은 이 파일을 열 수는 있지만 쓸 수는 없습니다.

**PDF**는 보고서에서만 나옵니다([보고서 유형](docs://ref-rapporttypes) 참조). 앱은 PDF를 읽지 않습니다.

**위치.** 열기: *홈 › 파일 › 열기*, *파일 › 열기* 또는 Ctrl+O. 내보내기: *홈 › 파일 › 내보내기* 또는 *파일 › 내보내기*. 채워진 진행률 시트는 *파일 › 가져오기*로 읽어 들이거나, *계획*, *테이블*, *보고서* 탭의 리본 그룹 *진행률*에 있는 버튼 *시트에서 진행률 업데이트*로 읽어 들입니다.

**열 때의 계산 프로필.** 모든 형식은 계산 프로필과 함께 열립니다. 계산 프로필이 무엇인지는 [계산 옵션과 규칙](docs://ref-rekenopties-en-conventies)에 있습니다. `.xer`는 *Primavera P6*으로, `.mpp`는 *Microsoft Project*으로 열립니다. CSV, MS Project XML, P6 XML은 *Open Planner Studio*로 열립니다. IFC는 파일에 저장된 프로필을 유지합니다. `.xer`과 `.mpp`의 경우 앱은 프로젝트가 이 방식으로 계산된다고 알려 줍니다. 계산 프로필과 계산 옵션을 담는 것은 IFC뿐입니다. 계산 옵션 중에서 MS Project XML은 주공정 임계값까지만 기록합니다. 다른 형식으로 내보낸 파일을 다시 열면 *Open Planner Studio*로 계산됩니다.

## IFC

**열기** — 예, `.ifc`. 앱은 IFC 4.3을 읽습니다. 계산 프로필: 파일에 있는 프로필.

**저장** — 예. 저장하는 형식은 이것뿐입니다. *저장*은 프로젝트 전체를 IFC 파일로 씁니다. 이 파일이 저장 대상이 됩니다.

**내보내기** — 예, *IFC 4x3*으로 내보낼 수 있습니다(설명: *BuildingSMART 표준. BIM 모델과의 4D 연동.*). 기본 이름은 프로젝트 이름에 확장자 `.ifc`를 붙인 이름입니다. 프로젝트가 리소스 라이브러리에 연결되어 있으면 *파일 › 내보내기*의 카드 아래에 체크 상자 *라이브러리 파일도 함께 저장*이 있습니다. 이 상자를 선택하면 앱은 프로젝트 다음에 *projectname-bibliotheek.ifc* 저장 위치를 묻습니다. 이 체크 상자는 *홈* 탭의 목록에 없습니다.

**함께 넘어가는 것** — 프로젝트에 속한 모든 것입니다. 구조, 기간, 날짜, 진행률이 있는 작업. 지연이 있는 관계. 제약 조건과 기한. 달력. 시간 분배를 포함한 리소스와 할당. 기준선. 활동 코드와 사용자 지정 필드. 메모. 다른 프로젝트로의 외부 관계. 중단. 작업 규칙과 작업 유형. 상태 날짜, 진행 모드, 계산 프로필, 계산 옵션 같은 프로젝트 설정. 리소스 라이브러리와의 연결. `.xer`에서 가져온 프로젝트라면 원본 파일도 함께 넘어갑니다. 사용자 지정 작업 유형은 IFC 유형 `USERDEFINED`로 저장되고, 이름은 ObjectType 필드에 들어갑니다. 그래서 다른 IFC 프로그램도 작업을 정상적으로 읽습니다. 앱은 또한 유형의 고정 ID를 보관하므로 이름을 바꿔도 연결이 끊어지지 않습니다. 다른 컴퓨터에서 파일을 열면 그 유형은 *이 프로젝트에서* 아래에 나타납니다. 그 사람의 *내 작업 유형*에는 나타나지 않습니다.

**넘어가지 않는 것** — 화면 설정(확대/축소, 스크롤 위치, 선택한 작업, 접힌 단계, 선택한 필터와 그룹화)과 앱 설정([설정](docs://ref-instellingen)). *IFC* 탭에는 프로젝트의 IFC 텍스트가 표시됩니다.

## MS Project XML (MSPDI)

**열기** — 예. 앱은 MS Project 네임스페이스의 루트 요소 `Project`(또는 네임스페이스가 없는 경우)로 `.xml` 파일을 MS Project XML로 인식합니다. 계산 프로필: *Open Planner Studio*.

**저장** — 아니요. 이런 프로젝트에는 저장 대상이 없습니다.

**내보내기** — 예, *MS Project XML*로 내보낼 수 있습니다(*Microsoft Project에서 열 수 있습니다. 전체 WBS 구조.*). 기본 이름은 프로젝트 이름에 `.xml`을 붙인 이름입니다.

**함께 넘어가는 것** — 구조(수준과 WBS), 기간, 날짜, 진행률이 있는 작업. 시간이나 백분율로 된 지연이 있는 관계. 기한을 포함한 제약 조건. 작업 달력과 리소스 달력을 포함한 달력. 곡선 또는 시간 분배를 포함한 리소스와 할당. 상태 날짜. 0 이상의 정수인 근무일 수로 된 주공정 임계값(*총 여유 ≤ 임계값*). 작업 설명(메모로). 작업의 작업 규칙(MS Project 작업 유형으로). 자유 필드(`ExtendedAttribute`)에 담긴 사용자 지정 작업 유형. 앱은 이 필드를 다시 읽지만, MS Project는 무시할 수 있습니다. 기준선 중에서는 활성 기준선만 기준선 0으로 넘어갑니다. 시간 단위 작업은 단위를 유지하고, 마일스톤은 종류(시작, 완료 또는 자동)를 유지합니다.

**넘어가지 않는 것** — 메모(작업의 체크리스트), 다른 프로젝트로의 외부 관계, 활동 코드와 사용자 지정 필드, 두 번째 제약 조건, *수동 일정* 표시, 평준화 지연, 순서 위반 작업의 재개 지점과 중지 지점, MS Project 프로필의 규칙 *남은 작업은 경과 기간 후에 재개*와 *시작되지 않은 작업을 상태 날짜로 옮기지 않음*, 그리고 나머지 계산 옵션. 시간 분배가 없는 중단된 작업은 중단 없이 넘어갑니다.

**도중에 바뀌는 것** — 옵션 *필수(고정 로직)* 없이 제약 조건 *지정일에 시작 (MSO)* 또는 *지정일에 완료 (MFO)*는 *지정일 이후 시작 (SNET)* 또는 *지정일 이후 완료 (FNET)*가 됩니다. 해먹은 계산된 날짜를 가진 일반 작업이 됩니다.

## MS Project 파일 (`.mpp`)

**열기** — 예. MS Project 2010부터 2021까지 지원합니다. 계산 프로필: *Microsoft Project*. 앱은 파일을 읽기만 합니다. `.mpp` 파일은 절대 바꾸지 않습니다. 앱은 MS Project 2007 이하 파일과 암호가 걸린 파일을 열지 않습니다. 이때 앱은 MS Project의 XML 내보내기를 안내하는 메시지를 표시합니다.

**저장** — 아니요. 저장 대상도 없습니다. *저장*은 새 IFC 파일을 씁니다.

**내보내기** — 아니요.

**함께 넘어가는 것** — 구조, 기간, 제약 조건이 있는 작업. 지연이 있는 관계. 달력. 리소스와 할당. 진행률. MS Project에서 직접 입력한 WBS 코드. MS Project가 직접 계산한 날짜와 여유도 읽습니다. 이 날짜와 여유는 보기 *기록된 날짜*에 표시하기 위해 함께 읽습니다.

**넘어가지 않는 것** — 기준선, 비용과 단가, 메모, MS Project의 사용자 지정 필드. [MS Project 파일(.mpp) 열기](docs://howto-mpp-openen)를 참조하세요.

**출처와 라이선스** — `.mpp` 리더는 Open Planner Studio를 위해 작성되었습니다. LGPL-2.1 라이선스의 Java 라이브러리 MPXJ(`github.com/joniles/mpxj`, Jon Iles 외)의 소스 코드와 구조에 관한 지식을 바탕으로 합니다. 구조와 필드 상수는 TypeScript로 옮겼습니다. Open Planner Studio 자체는 LGPL-3.0에 따른 오픈 소스입니다. `.xer` 리더는 파생물이 아닙니다. 거기서는 MPXJ를 이해를 위한 자료로만 참고했습니다.

## Primavera P6 XML

**열기** — 예. 앱은 루트 요소 `APIBusinessObjects`로 `.xml` 파일을 P6 XML로 인식합니다. 계산 프로필: *Open Planner Studio*.

**저장** — 아니요.

**내보내기** — 예, *Primavera P6 XML*로 내보낼 수 있습니다(*Oracle Primavera P6용.*). 기본 이름은 프로젝트 이름에 `.xml`을 붙인 이름입니다. MS Project XML 내보내기와 같은 이름이 됩니다. 직접 다른 이름을 지정하세요.

**함께 넘어가는 것** — WBS 구조와 기간, 날짜, 진행률이 있는 작업. 지연이 있는 관계. 제약 조건(두 번째 제약 조건도 소프트 제약 조건으로). 달력. 리소스와 할당. 상태 날짜(`DataDate`로). 자체 필드 `OPS Custom Task Type`에 담긴 사용자 지정 작업 유형. 앱은 이 필드를 다시 읽지만, P6는 무시할 수 있습니다.

**넘어가지 않는 것** — 기준선과 기한. 활동 코드, 사용자 지정 필드, 메모, 외부 관계. 계산 옵션. P6에는 백분율 지연이 없습니다. 앱은 이를 고정된 일수로 변환합니다. 달력 일 기준 지연은 근무 시간 기준 지연이 됩니다. 예: 달력 3일은 근무일 3일이 됩니다. 해먹은 일반 작업이 됩니다. 수동 일정 작업은 계산된 날짜를 가진 일반 작업이 됩니다. 하루보다 짧은 평준화 지연은 버려집니다.

## Primavera 파일 (`.xer`)

**열기** — 예. 계산 프로필: *Primavera P6*. 앱은 파일을 읽기만 합니다. `.xer`을 쓰지 않으며 파일을 절대 바꾸지 않습니다. 작업이 있는 프로젝트마다 탭 하나를 엽니다. 작업이 없거나 테이블이 손상된 파일은 열지 않고 메시지를 표시합니다.

**저장** — 아니요. 저장 대상도 없습니다. *저장*은 새 IFC 파일을 씁니다. 원본 `.xer`이 그 안에 들어갑니다.

**내보내기** — 아니요. `.xer`에서 가져온 프로젝트를 CSV, MS Project XML 또는 P6 XML로 내보내면 앱은 XER 원본 정보가 손실된다고 알립니다. 중간에 IFC로 저장했더라도 마찬가지입니다. IFC로는 아무것도 손실되지 않습니다.

**함께 넘어가는 것** — WBS 구조와 기간, 날짜, 제약 조건, 진행률이 있는 작업. 지연이 있는 관계. 달력. 할당이 있는 리소스. 활동 코드. 사용자 지정 필드(UDF). 메모. P6의 일정 설정. 유형이 *Level of Effort*인 작업은 해먹이 됩니다. 기준선 프로젝트는 그 프로젝트를 참조하는 프로젝트의 활성 기준선이 됩니다. 두 프로젝트 사이의 관계는 앱이 원본 데이터로 보관합니다.

**넘어가지 않는 것** — 작업이 없는 프로젝트, 그리고 두 프로젝트 사이의 관계가 일정의 실제 관계로 들어가는 것. [Primavera P6 파일(.xer) 열기](docs://howto-xer-openen)를 참조하세요.

## CSV

**열기** — 예. 앱은 `;`과 `,`를 구분 기호로 읽습니다. 열 머리글은 영어와 네덜란드어로 인식합니다(예: `Name` 또는 `Naam`, `Duration` 또는 `Duur`, `Predecessors` 또는 `Voorgangers`). 날짜는 *년-월-일*, *일-월-년* 또는 *dd/mm/yyyy* 형식일 수 있습니다. 선행 작업은 WBS 코드, 관계 유형, 지연으로 씁니다. 예: `1.2FS+2d`. 계산 프로필: *Open Planner Studio*. 프로젝트 이름은 *CSV Import*입니다. 앱이 직접 쓰는 고정 코드(예: `CONSTRUCTION` 또는 `INSTALLATION`)가 아닌 `Task Type` 값은 *이 프로젝트에서* 아래의 사용자 지정 작업 유형이 됩니다. *내 작업 유형*에는 나타나지 않습니다. `OPS Custom Task Type ID`가 있으면 사용자 지정 유형의 ID가 유지됩니다.

**저장** — 아니요.

**내보내기** — 예, *CSV (;)*로 내보낼 수 있습니다(*범용 테이블 내보내기. 날짜 및 기간이 포함된 모든 작업.*). 카드 *CSV (세미콜론 구분)*에서 선택합니다. 파일은 세미콜론을 구분 기호로 쓰고, BOM이 포함된 UTF-8이며, 열 머리글은 영어입니다.

**함께 넘어가는 것** — 작업마다 다음 열이 들어갑니다: `OPS Task ID`, `WBS`, `Outline Level`, `Name`, `Duration (days)`, `Start`, `Finish`, `Predecessors`, `Task Type`, `OPS Custom Task Type ID`, `Status`, `Completion (%)`, `Actual Start`, `Actual Finish`, `Critical`, `Total Float`, 그리고 `Description`. 완료율은 정수 백분율입니다.

**넘어가지 않는 것** — 리소스, 할당, 달력, 제약 조건, 기한, 기준선, 상태 날짜. 날짜가 *기록된 날짜* 보기에 있으면, 원본 파일에 그 값이 기록되지 않은 작업에서는 내보내기가 `Critical`과 `Total Float`를 비워 둡니다.

## 진행률 시트 (Excel 및 CSV)

**열기** — 예. *파일 › 가져오기*(*시트에서 진행률 업데이트*)로 열거나, *계획*, *테이블*, *보고서* 탭의 리본 그룹 *진행률*에 있는 같은 이름의 버튼으로 엽니다. 앱은 `.xlsx`과 `.csv`를 읽습니다. 최대 16 MB, 50,000행까지입니다. 이 기능은 프로젝트를 열지 않습니다. 열린 프로젝트의 진행률을 업데이트합니다. 자세한 내용은 [시트에서 진행률 가져오기](docs://howto-voortgang-importeren)를 참조하세요.

**저장** — 아니요.

**내보내기** — 예, *진행률 시트(Excel)*(목록에서는 *진행률(Excel)*)와 *진행률 시트(CSV)*(목록에서는 *진행률(CSV)*)로 내보낼 수 있습니다. 기본 이름은 *projectname-voortgang*입니다. 같은 리본 그룹의 버튼 *진행률 시트 내보내기*를 누르면 Excel 시트가 한 번에 만들어집니다. Excel 시트는 열 너비가 고정되어 있고, 필드가 잠겨 있으며, 날짜를 검사합니다. CSV 시트는 같은 내용의 일반 텍스트입니다.

**함께 넘어가는 것** — 열 `OPS Task ID`, `WBS`, `Name`, `Start`, `Finish`, `Completion (%)`, `Actual Start`, `Actual Finish`. 읽어 들일 때 앱은 `Completion (%)`, `Actual Start`, `Actual Finish`를 사용합니다. `Start`와 `Finish`는 날짜 표기를 인식하는 데만 쓰이며 일정을 바꾸지 않습니다. 앱은 행을 `OPS Task ID`로 작업에 연결합니다. 그 값이 없으면 고유한 WBS 코드로 연결합니다.

**넘어가지 않는 것** — 이 열 밖의 모든 것: 기간, 관계, 리소스, 일정의 나머지 부분. 요약 작업은 시트에서 진행률을 받지 않습니다.

## PDF

**열기** — 아니요.

**저장** — 아니요.

**내보내기** — 예, 보고서에서 내보냅니다. *보고서* 탭의 버튼 *PDF 내보내기*를 사용합니다. 앱은 보고서를 프린터로 직접 보내지 않습니다. 종이로 출력하려면 PDF를 거칩니다. 내용은 보고서 유형에 따라 다릅니다. 자세한 내용은 [보고서 유형](docs://ref-rapporttypes)과 [보고서 만들기와 출력](docs://howto-rapport-maken-en-afdrukken)을 참조하세요.
